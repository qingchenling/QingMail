## 2. P2 剩余工作，逐项核对

### A. 发送闭环收尾

依据：主基线 §4.4、ADR-0005、P1 规格“写信、草稿与发送”。

- 已完成（P2-011）：IMAP 已发送文件夹定位（优先沿用上次记录的文件夹，否则按常见名称与叶子名选择可选文件夹）、按冻结 Message-ID 先查重、APPEND 同一份确定性重建的 MIME、记录 APPENDUID；只有确认保存或查重命中才进入 Sent。失败/不确定保持 CopyPending 并记录固定诊断代码；写信窗口提供“重试保存副本”，重试只走 IMAP 并先查重，绝不再次 SMTP 提交。
- 仍需：明确失败后的修改/重发、不确定后的查看已发送/二次确认重发/停止处理。存储层已有 `resend_task/stop_uncertain` 和旧记录保留规则，但网络与产品入口尚未接入；目前有发送记录的草稿一律被阻止再次提交。
- 仍需：任务入口与持续、脱敏且可操作的失败原因。目前只在编辑窗口显示至多50条记录、固定诊断类别及副本失败代码，没有独立的发送任务页面。
- 仍需：网络等待与退出反馈收尾。当前仍只有单次 socket 超时，DNS 与整次 SMTP 提交、副本保存都没有独立总期限，慢网络可能使“保存并退出”长时间等待；需验证和约束等待，不能把强制断开误报为未发送。

### B. 回复与基础富文本、草稿失败处理

依据：主基线 §6.2、ADR-0006、P1 规格“写信、草稿与发送”及实现门槛。

- 回复、全部回复、转发：从当前邮件生成正确收件人/主题及清理后的可编辑引用，连接现有草稿与发送流程；目前没有这些入口。
- 列表/引用/签名的正文编辑反馈与必要续项行为、清理后的基础 HTML 粘贴；目前区块主要靠右侧预览，粘贴只有纯文本。补齐基础格式选择/链接交互，不另造复杂 HTML 编辑器。
- 草稿保存失败已有重试及保留窗口，补齐规格中的另存文件、坏草稿恢复/明确放弃入口；附件导入/保存失败不能绕过发送门槛。现有可靠保存、多草稿和附件保护沿用。
- 中文斜体按操作者已接受的字体缺字形限制继续记录，不新增字体工程。按词撤销合并、复杂嵌套引用等原型改进建议不单独升格为 P2 功能门槛；基础富文本范围不降级。

### C. 单账号收信与基本邮件操作

依据：主基线 §4.3、§9，P1 阶段总结“增量同步”，P1 规格“列表与阅读”。

- 持续收信、断线/重开恢复、凭据失效后的恢复；远端删除及文件夹变化对账，保持稳定定位，不把90天范围之外的邮件误删。目前每次手动 LIST/EXAMINE/SEARCH 后取头部，仅追加/更新当前批次。
- 落实最近90天之外的主动历史加载；现有“下一页缓存”与90天内分页不能冒充历史加载。IDLE/低频轮询、暂停及退避属于原同步要求，围绕单账号实现，不增加多账号调度或 CONDSTORE/QRESYNC 专项。
- 已读/未读、星标、归档/移动/删除及基本批量/撤销反馈仍缺。它们来自主基线 §1.1 与 P1 列表/阅读规格；当前只读实现不能视为已完成邮件操作。P2 接入单账号在线操作与明确失败反馈，P3 再做持久离线操作队列与冲突完善。
- 阅读附件尚非按部分下载：现为 `BODY.PEEK[]`，首次打开同时下载内含附件，总邮件上限8MiB。与 §4.3“附件主动下载”有差距，需完成按需获取或明确产品取舍；不能悄悄把现状改写成已满足要求。超限提示已有，不额外承诺无限大小。

### D. 账号管理

依据：主基线 §1.1/§4.2、P1 规格“添加账号与管理”。

- 添加路径已有；仍需修改配置后重新检查、更新凭据/重新认证，以及本地移除账号的确认和处理（说明缓存/未发送草稿影响，不删除远端邮件）。当前界面和存储只有新增/枚举/读取账号。
- 密钥库锁定/不可用和认证错误已有分类提示；将恢复动作接到同一账号，避免只能重复添加或留下不可恢复配置。不扩展 OAuth，也不新增全盘密钥扫描工程。

### E. 本地搜索与正式界面整合

依据：主基线 §6.1、P1 规格 §1～5，尤其明确的“P2 搜索已下载内容”。

- 本地关键词、发件人、是否有附件筛选及范围/不完整提示、清空恢复位置。当前主窗“搜索”仅是 P0 输入演示，没有产品搜索或索引查询。
- 将账号添加→文件夹列表→阅读→回复/写信/账号草稿→发送任务连成正式入口，移除首页的 P0 合成展示。保留账号文件夹树、左侧直角；宽窗列表/阅读、窄窗返回、分隔线与位置记忆、焦点/键盘和基本多选按已确认规格落地。现有能力仍散在独立技术窗口。
- 接入已确认的收件人 chips、Cc/Bcc 按需展开、字段错误定位，以及主题/字号/列表密度/减少动态的必要设置。阅读字号与系统省电行为已有，不重复做动效性能排障。阅读窗口已有“立即清理副本”，产品整合时保留入口，不重复开发。通知/自启动等设置随 P4 功能落地，不先造空壳。

### F. 一次集中验收与 P2 总结

依据：主基线 §9/§10、P1 阶段总结。

- 完成前述实现后集中检查真实 Secret Service 与一个通用 IMAP/SMTP 账号的添加、同步、阅读、回复/草稿、附件、发送及已发副本；具体测试收件人与内容须由操作者授权。当前报告没有真实投递证据。
- 对相关故障集中回归：断网/认证失效、UIDVALIDITY、发送拒绝/结果不确定、APPEND 失败、重复点击、关窗/退出与崩溃重启；复用已有测试，修复发现的问题，不逐小步重复全套端到端。
- 检查整合后的明暗/焦点/快捷键/中文 IME/窄窗与适用缩放，记录持续使用、重启可靠和无重复发送证据，产出 P2 总结。未测的多显示器/浏览器条件如实标注，不把原型局部验收扩成全阶段通过。

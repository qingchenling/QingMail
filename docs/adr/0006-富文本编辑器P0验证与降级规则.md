# ADR-0006：富文本编辑器在 P0 独立验证，降级须以 ADR 决定

- 状态：已接受
- 日期：2026-11-16
- 关联：主文档 §1.1、§6.2、§9（P0）、§11

## 背景

首版要求基础富文本写信（段落、粗体、斜体、基础列表、链接、引用、签名、附件），并约束不引入 WebView 编辑器。GPUI Kit 的 TextView 是阅读组件，不能假定其提供可编辑富文本；gpui-base 提供编辑原语，但中文输入法、撤销/重做、选区、粘贴、格式切换和草稿序列化的可行性未经验证。这是全项目最大的单点技术风险。

## 决策

1. 富文本编辑是 P0 的独立验证项，与其他原型工作并行推进；验证内容：中文输入（含 IME 组合输入）、撤销/重做、选区与光标、粘贴、格式切换、草稿序列化、自动保存不阻塞输入。
2. 验证产出为差距报告：已验证能力、未验证项、限制与证据，不得以"编译通过"或组件展示页代替实测。
3. 若验证失败或能力不足：提交差距报告后，通过新的 ADR（或修订本 ADR）明确降级方案与范围变更（例如先交付纯文本 + 后续恢复富文本），不擅自把交付范围改成纯文本，也不静默保留不可用的富文本承诺。
4. 编辑器采用受控文档模型保存草稿，发送时导出 text/plain 和受控 text/html；回复和转发的引用内容必须先清理，不把不可信原始 HTML 直接塞回编辑器。

## 后果

- 最大技术风险在项目最早期暴露，为 P1 产品设计和 P2 交付范围提供事实依据。
- 存在 P0 后首版范围调整的可能；调整必须留有 ADR 记录，保持决策链完整。
- 若 GPUI 原生能力最终无法满足，备选路径（如自研受限编辑组件）进入差距报告评估，而不是立即引入被排除的 WebView 方案。

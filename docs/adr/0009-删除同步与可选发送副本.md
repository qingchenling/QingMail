# ADR-0009：删除同步与可选发送副本，IPC v3

- 日期：2026-11-19
- 状态：接受（用户明确要求）
- 关联：ADR-0005、ADR-0007、ADR-0008

## 决策

1. 设置为“发送后保存到发件箱”，默认开启（后续用户要求，取代初始的默认关闭）；schema23升级时一次性启用偏好，此后可关闭并持久保存。由后台单写者持久保存。确认新发送任务或明确重发时冻结选择；SMTP 接受后，关闭者直接进入 Sent，开启者沿用 CopyPending → Sent。已有发送任务迁移时保留原来保存副本的策略。任何分支不得自动重发；服务商自行保存的副本不受客户端开关控制。
2. 普通邮件删除先同事务持久化意图和本地隐藏效果，后台移到对应账号的垃圾箱；目标名称从账号目录解析后冻结，不要求先同步目标索引，不虚构目标 UIDVALIDITY。失败、认证异常、UIDVALIDITY 改变及结果不确定继续沿用既有队列处理。
3. 草稿的用户删除同时排队处理所有已明确关联的服务器版本，并删除本地编辑副本；原始 MIME 证据和发送快照保留。没有远端关联的草稿只删除本地。上传结果未定、未解决冲突、缺少目标目录或写盘失败均保留草稿；普通扫描不得复活删除的同一副本。内部“放弃损坏本地草稿”等恢复入口继续使用本地 discard，不将恢复操作隐式扩大为服务器删除。
4. 垃圾箱中明确确认再次删除时，只对指定 UID 使用 STORE + UID EXPUNGE。服务器必须支持 UIDPLUS 或 IMAP4rev2；不支持则在写入前停止并提示。不使用全局 EXPUNGE。移动响应丢失不能自动重放；永久删除响应丢失可只读核对精确旧 UID 是否消失，不能据此删除新 UID。
5. schema19 顺序升级至20，保留迁移前备份与未来版本拒绝。新增后台偏好及发送任务冻结字段，扩展删除投影视图。
6. IPC 从 v2 升级至 v3：严格 DTO 新增偏好、Trash 操作，DiscardDraft 的用户语义也改变；旧端必须在写入前拒绝。前后台配套更新，不伪称旧版兼容。旧报告仍按当时协议版本理解。

## 界面

Drafts 共用邮件页的顶栏、分栏、列宽和底栏，只替换中间草稿列表与右侧编辑内容；不再进入独立页面或播放独立入场动画。保留原有保存、IME、冲突和生命周期协调。

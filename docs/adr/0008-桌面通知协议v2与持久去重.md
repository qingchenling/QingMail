# ADR-0008：桌面通知协议 v2 与持久去重

- 日期：2026-11-18
- 状态：接受（P4-001 允许严格消息扩展无法安全兼容时升级主版本）
- 关联：ADR-0005、ADR-0007、[P4-001 设计](../design/P4-001-日常使用与桌面集成设计.md)

## 背景

P3 的 IPC v1 使用严格枚举和未知字段拒绝。通知定位需要在前台激活消息中加入完整邮件身份；旧前台无法理解新激活变体。仅增加 Hello 命令列表不能保证旧前台在后续心跳收到未知激活之前拒绝写入。

## 决策

1. P4-002 将控制协议升级为 v2，沿用 NDJSON、有界二进制资源和同用户私有 socket。读取版本先于命令解码；v1/v2 混用在写入前拒绝。UI 与 daemon 必须同时更新，前台 Hello 校验桌面能力；不增加不完整的跨主版本转换层。
2. 桌面通知由 daemon 管理，在收件箱索引同一事务内更新 UIDVALIDITY/UID 基线和临时未读候选。候选只引用既有身份，不复制正文/头部；首次、历史、重建不产生旧信提醒。桌面偏好由 Store 单写者持久保存，外观配置仍由前台保存。
3. D-Bus 通知是尽力提醒，不是可靠邮件投递凭据。外部调用前持久消费候选；响应未知不重放。崩溃可能漏一次提醒，避免重启反复弹出；邮件索引仍保留可读。此选择不改变 SMTP 的禁止自动重发规则。
4. schema17 顺序迁移至18，沿用迁移前备份和未来版本拒绝。新增桌面偏好、通知基线、待合并区间及临时候选身份；完成、抑制或重建后清理候选，不保存永久通知中心。

## 影响

升级需先保存并退出旧前后台，再启动同一构建产出的两个程序。旧 P3 测试包不能连接新后台或读取 schema18；回退需按原迁移说明配套恢复完整数据备份，不能只替换数据库文件。无 OAuth、自动启动、SMTP 自动发送或图形栈升级。P3 历史报告继续按 v1/schema17 的当时事实解释。

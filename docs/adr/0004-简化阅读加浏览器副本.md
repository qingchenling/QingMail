# ADR-0004：HTML 邮件采用应用内简化阅读 + 浏览器副本，不内嵌 WebView

- 状态：已接受
- 日期：2026-11-16
- 关联：主文档 §2.2、§5、§10.1

## 背景

HTML 邮件的完整排版保真需要浏览器引擎。现有 gpui-webview 的 Linux 集成依赖 X11/XWayland，无法用于原生 Wayland 的 GPUI 窗口；引入离屏浏览器合成或内嵌 WebKitGTK/WPE/CEF 会显著增加构建复杂度、攻击面和资源占用，且与"不使用 WebView 构建应用界面"的项目约束冲突。

GPUI Kit 的原生 TextView 支持部分 HTML，但会丢弃样式表，不能保证复杂营销邮件、嵌套布局和响应式 CSS 的保真。

## 决策

1. 应用内提供"简化阅读"：HTML 经解析和清理后生成受控的简化文档（段落、标题、列表、引用、链接、图片、基础表格），保证可读、可选中、可复制；界面固定标识简化状态，并提供纯文本切换。
2. 复杂排版通过"在浏览器中打开"阅读：后台生成单个本地 HTML 副本（内嵌图片转为受控 data URI），交系统默认浏览器打开。副本处理规则遵循主文档 §5.3（删除脚本/iframe/表单/meta refresh，默认阻止远程资源，CSP 作为补充防护）。
3. 首版不引入内嵌浏览器引擎，WebKitGTK、WPE、CEF 不作为构建依赖。
4. 未来若重新评估内嵌引擎，须单独立项并以新 ADR 取代本决策，不改变当前交付标准。

## 后果

- 获得确定的安全边界和可控的资源占用，放弃应用内完整排版保真。
- 用户阅读营销邮件等复杂排版需跳转浏览器；该取舍通过界面标识与固定入口显式呈现，不静默降级。
- 原始邮件数据始终保留，简化文档与浏览器副本均为派生结果，可随时重建。

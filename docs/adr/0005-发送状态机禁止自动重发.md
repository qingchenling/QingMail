# ADR-0005：发送状态机区分"结果不确定"，禁止自动重发

- 状态：已接受
- 日期：2026-11-16
- 关联：主文档 §4.4、§10.2、§11

## 背景

SMTP 无法提供端到端提交确认：连接在最终接受阶段断开时，客户端无法判断邮件是否已发出。此时若自动重试，存在重复发送邮件给收件人的风险——这是邮件客户端最严重的行为事故之一，且不可逆。

## 决策

1. 发送任务至少区分六个状态：待提交、正在发送、发送成功、明确失败、结果不确定、已发副本待保存。
2. "结果不确定"（SMTP 在最终接受阶段断开且无法确认）时，任务保持该状态并明确告知用户，不自动重发；由用户决定重发或放弃。
3. 任务与附件引用先可靠持久化，再进行网络提交；进程重启后保留任务状态，恢复过程不得重复发送。
4. SMTP 已成功但 IMAP 保存"已发送"副本失败时，仅重试保存副本，不重发邮件。
5. 离线编辑的草稿在恢复网络后不得未经用户明确发送操作自动发出。
6. 失败重试仅适用于"明确失败"且语义幂等的分支，并受次数与抖动限制；任何分支不得无限静默重试。

## 后果

- 重复发送风险被结构性消除，代价是"结果不确定"场景需要用户介入。
- 发送队列必须持久化且带状态机测试覆盖（§10.2 的故障分支），不能用内存队列。
- 用户界面需要为"结果不确定"提供清晰的操作入口（查看、重发、放弃），在 P1 产品设计中纳入。

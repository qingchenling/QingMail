# 开发与验证

## 检查与构建

锁定依赖，不例行升级 GPUI 或工具链。本机 Rust 1.100.0 为 Arch 系统包，无 rustup；rust-toolchain.toml 只在 rustup 环境负责切换。声明的 MSRV 1.98 不等于已验证最低版本。

```sh
cargo fmt --all -- --check
cargo check --workspace --locked
cargo test -p mail-service --lib --locked parts::tests
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo build --release --locked -p mail-ui -p mail-daemon
```

测试过滤器按实际改动选择。日常只测试相关部分；工作区全量 `cargo test --workspace --locked` 留阶段收口或重大集中验证，不因文档整理、打包或小改动反复执行。真实GUI验收集中进行，修复后复测受影响流程。

## GPUI 约束

适用于当前锁定的 gpui-pre 0.3.12，来自早期原生窗口实测，后续窗口必须遵守：

1. `Window::request_animation_frame` 仅可在绘制阶段调用，事件回调使用 `on_next_frame`；后者自行调度帧。
2. `advance_component_theme` 由单一pump回调链推进，目标放入视图状态，每帧读取最新值；多条捕获旧目标的闭包链会互相覆盖。
3. 禁止同实体重入 `entity.update`。监听器内直接推进已有上下文，只在后续帧回调中更新实体。
4. 窗口使用 `ui::window_options()` 继承 app_id，与桌面入口及图标 `org.qingmail.QingMail` 一致；应用名称设置不能代替窗口app_id。
5. 普通运行遵循系统省电策略；流畅度测试记录电源模式。HUD的1/FRAME是推导值，不能当作合成器实际呈现帧率。

## 隔离测试

正式 `mail-ui` 默认读取真实XDG目录，不能作为离线演示直接操作。现代跨进程探针使用 `QINGMAIL_IPC_ROOT=<绝对私有目录>`，由前台连接同目录配套 `mail-daemon --isolated-root`；隔离后台禁止邮件网络和真实密钥库访问。

早期原生控件探针仍有用途，使用 `QINGMAIL_P0_DRAFT_ROOT` / `QINGMAIL_P0_RUNTIME_ROOT` 及各自参数。这些覆盖参数本身不是禁止联网或发送的开关；按工具实现的成组隔离环境运行，不能将其中一个参数当作隔离正式账号的保证。不要手工将合成夹具写入正式数据库。

| 工具 | 用途 |
| --- | --- |
| `generate_mime_fixtures.py`、`tests/fixtures/mime/` | 合成MIME样本；阅读器含编译期引用，不能当临时文件删除 |
| `browser_resource_probe.py`、`mail-content/examples/reading_copy.rs` | 真实Firefox排版与资源请求探针，验证清理/CSP，不能只做字符串断言 |
| `account_probe.py`、`editor_storage_probe.py`、`compose_fields_probe.py`、`send_review_probe.py` | 隔离表单、编辑器协议/持久化、收件字段与发送预览；发送预览不确认投递 |
| `body_reading_probe.py`、`mailbox_probe.py`、`mailbox_ui_probe.py` | 缓存、正文/浏览器、列表与界面回归 |
| `inline_compose_probe.py` | 主窗口写信整合：单窗口、多草稿、IME/格式/发送预览、选信保存、失败保留和退出刷新（隔离数据，不发送） |
| `lifecycle_probe.py`、`p3_split_probe.py` | 旧本地诊断及正式跨进程生命周期、保存/重开/重连/崩溃验证 |
| `p3_real_account_probe.py` | 明确授权后的真实IMAP收信/草稿验证，不调用SMTP；不要无授权运行 |
| `performance_probe.py`、`cached_performance_probe.py`、`window_performance_probe.py`、`test_performance_probe.py` | 受控五账号、索引、原生窗口及采样资格回归；窗口可选只读Hyprland app_id核验 |
| `build_arch_package.py`、`arch_package_probe.py` | 本地Arch源码快照打包及隔离包事务；后者需fakeroot，不用sudo操作主机库 |

工具均位于 `tools/`。CLI参数优先看各工具的 --help（部分早期工具固定流程，先读文件头及入口）；具体依赖、命令和有效测量条件见 [性能报告](reports/P4-004-性能与体验基线.md)、[安装包报告](reports/P4-005-Arch安装包与桌面入口.md) 和 [合成样本说明](../tests/fixtures/mime/README.md)。

测试可能需要可用Wayland会话、本地Unix socket、Firefox/WebDriver、Python websockets、私有D-Bus/测试密钥库等；缺少环境应明确报告，不把无法启动当作业务失败或已通过。真实网络/系统配置变更、登录及休眠人工验收按授权执行。

## 维护与证据

数据库修改沿用顺序迁移、升级前备份和未来版本拒绝；不删除旧schema SQL。测试样本、故障注入、协议兼容测试与仍可复用的探针属于维护资产，不因阶段完成删除。模块复用入口先查 [模块地图](项目全貌与模块复用说明.md)。

探针的新输出默认放在忽略的 `dist/verification/`，需要归档时显式指定路径或择要保存。当前关键验收证据保留在 `docs/reports/evidence/`；实际结论统一在 [验证记录与已知限制](验证记录与已知限制.md)。旧阶段逐轮报告、原型图和中间日志从工作区移除后，可在Git历史中查阅；不要再次把旧“尚未实现”搬成现状。

`dist/`只放可再生构建产物，保留当前预览包/源码/校验和；`target/`是Cargo缓存，可按需cargo clean，但不作为日常整理反复清空。用户XDG数据、凭据、草稿与配置不属于仓库清理对象。

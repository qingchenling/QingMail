# P1-001 · 产品交互规格（首轮评审）

日期：2026-11-16。状态：待用户评审，P1 尚未退出。
依据：项目构建与开发交接文档 §6/7/9/11、ADR-0001～0006、P0 阶段总结。

本轮定义产品行为，不代表真实邮箱功能已经实现。交互预览使用合成数据、不会连接服务器或发送邮件；产品继续使用 Rust + GPUI Kit + Material 原生窗口。预览不作为产品运行时依赖。

## 1. 范围与信息架构

- P2：一个通用 IMAP/SMTP 账号的添加、同步、文件夹、单封列表、阅读、回复/转发、草稿、附件和明确发送闭环。
- P3：多账号、统一收件箱、完整离线能力及 daemon/IPC 拆分。P1 定义这些界面位置，P2 不显示不可用的空壳入口。
- Gmail/Outlook OAuth 最早 P4；账号页明确说明本轮仅通用 IMAP/SMTP，不索取不适用的普通密码。
- 无会话聚合、日历、联系人管理、AI、PGP、复杂表格和导出备份。

导航顺序：写信；统一收件箱（P3 多账号时）；账号文件夹树；发送任务；设置。左侧以账号为父节点，各账号独立展开/收起自己的收件箱、草稿、已发送、归档、垃圾邮件、已删除及服务器自定义文件夹；草稿不再作为脱离账号的全局平级入口。展开账号不改变当前阅读，点击子文件夹才切换账号与列表；折叠后保留当前选择和各账号展开状态。P2 单账号沿用同一层级，P3 加入更多账号。文件夹树靠齐窗口左边缘，左上/左下和树节点均为直角，不使用圆角卡片或胶囊式文件夹行。搜索位于窗口顶部，保持当前账号/文件夹范围可见。账号管理可从设置或账号菜单进入。

## 2. 布局、密度与焦点

尺寸均为逻辑像素，以下是首轮设计值，GPUI 实现时须在 100/125/150/200% 实测，不视为已通过。

| 窗口宽度 | 布局与行为 |
| --- | --- |
| ≥1100 | 导航 208 + 列表默认 340 + 阅读剩余空间；阅读正文最大行宽 760 |
| 760–1099 | 导航收为可打开的抽屉；列表默认 300 + 阅读；允许主动隐藏列表 |
| <760 | 单面板，默认列表；打开邮件后以“返回列表”恢复原位置；导航为抽屉 |

分隔线可拖动；导航 176–280、列表 280–480，记忆尺寸但受当前可用空间约束。不得强制窗口位置或用过大最小尺寸撑屏。写信使用独立原生窗口，窄窗字段与格式工具换行，尊重平铺布局。

列表默认每行 68，发件人/时间、标题、摘要三层；可设紧凑 56。已读与未读同时用字重和标记区分。无标题显示“（无主题）”；无头像用姓名首字；邮箱/标题省略显示但可通过详情取得全文。列表虚拟化、分段加载；翻页不跳滚动位置。

- 单击选择并阅读；焦点外框与选中底色分离；复选框只负责批量选择，不改变当前阅读。
- Shift 连选、Ctrl 点选；批量工具栏显示数量，删除/移动失败保留失败项，不清空全部选择。
- Tab 按导航→搜索→列表→阅读工具→正文移动；方向键只在有焦点的列表内选邮件。编辑字段内不触发单键邮件动作。
- 切换文件夹恢复各自滚动位置；加载后不抢焦点；空列表不自动聚焦删除等危险操作。

## 3. 关键页面与完成路径

### 添加账号与管理

首次启动只显示欢迎与“添加通用邮箱”。步骤：显示名称/邮箱→IMAP 与 SMTP 主机、端口、加密方式、用户名、密码或应用专用密码→检查连接→确认保存→收件箱首次同步。

默认 IMAP 993 隐式 TLS、SMTP 465 隐式 TLS；支持显式选择 STARTTLS（通常 587），必须验证证书，不提供忽略证书的快速操作。更改加密方式时提示检查端口，不静默改掉用户输入。两个服务可使用不同凭据。

分别展示 IMAP/SMTP 检查结果：DNS/连接超时、认证失败、证书失败分开；错误保留非敏感字段。密钥库锁定提供“解锁后重试”；密钥库缺失说明无法安全保存，不把密码写入普通配置。检查通过后仍需用户确认保存，避免把连通性当账号成功。

账号管理：修改连接信息需重新检查；移除账号明确影响本地缓存和未发送草稿，列出数量并提供取消。远端邮件不因移除本地账号而删除。

### 列表与阅读

顶部显示当前文件夹、同步状态、搜索范围。初次同步显示阶段和已获取数量，不伪造进度百分比、不逐封发通知。空文件夹、尚未同步和筛选无结果使用不同空态。

阅读顶部：发件人、收件人详情、时间、主题；回复/转发/移动/删除。正文固定标识“简化阅读”，可切换纯文本、字号，并始终可找到“在浏览器中打开”。不以“原始网页”描述安全副本。

远程资源默认拦截：“已阻止远程图片，加载可能暴露阅读行为”。“仅此邮件加载”需明确动作；无全局静默授权。附件显示名称、类型、大小，保存时选择位置，失败可重试；未知类型不直接执行。浏览器入口反馈“已交给系统打开”，不宣称浏览器启动成功；失败提供重试和副本位置。

正文失败显示可用纯文本或可读错误；损坏 MIME 不阻断其他邮件。删除后提供撤销；远端拒绝时恢复并显示原因，不把本地动画当服务器成功。

### 写信、草稿与发送

收件人 chips 可展开完整地址；Cc/Bcc 按需展开；无主题发送前确认。收件人格式错误定位到字段；附件上传/保存未完成、草稿写盘失败时不能进入网络提交。

编辑支持段落、粗体、斜体、基础列表、链接、引用、签名和附件。回复/转发先清理引用，草稿模型统一导出 plain + HTML；HTML 粘贴走清理，不能执行资源。中文斜体缺字形、区块编辑等 P0 差距仍待实现，不把预览当能力验收。

底部保存状态：未保存→正在保存→已保存（时间）；失败为持续提示，提供“重试保存 / 另存到文件 / 保留窗口”。关闭时先完成保存；失败不可静默关窗。坏草稿保留原文件，提供恢复副本/另存/明确放弃，不自动覆盖。

发送按钮为唯一提交入口；按下后先持久化发送快照及附件引用，再进入任务。发送中防止同任务重复点击。离线时提示“草稿已保存，联网后请再次点击发送”，不排队自动发出。

| 状态 | 文案与操作 |
| --- | --- |
| 待提交 | 正在保存发送任务；未持久化前不联网；此阶段可取消 |
| 正在发送 | 正在交给邮件服务器；禁重复提交；关闭写信窗口不取消后台任务 |
| 发送成功 | 已发送；查看已发邮件/新建邮件 |
| 明确失败 | 未发送：具体原因；修改草稿/明确重新发送；内部仅安全幂等分支有限重试 |
| 结果不确定 | 服务器可能已收到邮件，不会自动重发；查看邮件/查看已发送/重新发送/停止处理 |
| 已发副本待保存 | 邮件已发送，副本尚未保存；仅“重试保存副本”，不得再次 SMTP 发送 |

“重新发送”二次确认：“收件人可能已经收到上一封邮件。仍然发送一封新邮件？”；确认后创建新任务，旧任务留可追踪记录。“停止处理”只终止本地后续处理，不撤回远端邮件。查看已发送未找到邮件也不等同于未发送。

崩溃恢复：保留未完成任务，正在发送按持久化证据恢复为不确定或安全状态；不能一律回到待提交。不确定状态只由用户决策。任务页和对应草稿都能定位状态。

### 搜索

默认当前文件夹，范围菜单显式切账号/所有本地邮件（多账号 P3）。P2 搜索已下载内容，显示“搜索本地缓存，可能不含尚未下载的邮件”，不伪装完整服务器搜索。关键词、发件人、是否有附件为基础筛选；清空恢复原文件夹位置。无结果提供清空筛选。

### 设置与桌面行为

主题跟随系统/浅色/深色；字号；列表密度；减少动态效果（同时尊重系统省电）。通知隐私：完整/仅发件人/仅“收到新邮件”/关闭，默认仅新邮件提示；不把正文或账号秘密写入诊断日志。

缓存默认 1 GiB 可调整；清理缓存前说明不删除草稿、待发送快照和任务附件；单独清理浏览器阅读副本。后台运行、自启动为用户可选，不默认更改桌面配置。

关闭主窗：后台启用且托盘可用时继续同步；缺托盘时保留可恢复入口并提示，不静默藏后台。托盘菜单：打开、暂停/恢复同步、保存并退出。通知不可用仅在状态入口提示，不妨碍阅读。通知点击通过稳定邮件 ID 定位，已删除显示“邮件已移动或删除”。

退出等待草稿保存，任务只停止于可恢复状态；失败提供重试/取消退出/明确放弃未保存改动。系统强制退出只承诺恢复最后确认保存版本。

## 4. 组件与主题基准

原生 Material 组件优先：按钮（主要/次要/危险）、带说明的字段、菜单、对话框、导航项、列表行、任务状态条、附件条目、非阻塞提示。错误必须同时有文字与动作；关键失败和不确定发送不能仅用短暂 toast。

## 6. 实现门槛与评审

| 工作项 | 后续门槛 |
| --- | --- |
| 编辑器 P0 差距 | P2 写信发布前补齐；改变基础富文本范围必须新 ADR |
| 多草稿/缓存/任务 | 正式 XDG 目录、原子保存、密钥库、故障恢复，不复用 target 单槽 |
| 发送异常 | 六状态 + 故障注入 + 禁重发回归测试 |
| 界面 | GPUI 明暗/焦点/IME/缩放/窄窗实测，不能以本设计预览替代 |
| 性能 | 虚拟列表、静止资源预算、实际呈现帧率，不以 HUD 推导值冒充 |

首轮评审路径：添加通用账号→列表阅读及资源拦截→回复/草稿→发送不确定与副本失败→搜索→设置→窄窗返回。

P1 退出前必须获得用户对主要使用流程的确认，并记录修订；本文件和交互预览只是首轮提案。用户确认设计不等于批准发送真实邮件。P2 真实账号凭据和外部发送将单独按用户授权操作。

# P4-004 性能与体验基线

日期：2026-11-18。状态：测量工具、相关修复及自动专项已交付；五账号受控后台长测因私有密钥库崩溃无效。**全部桌面体验尚未验收**，空闲绘制的波动仍需定位，显示/恢复和非空闲场景在 P4-006 集中核实。本轮没有访问真实邮箱、系统密钥库、发送 SMTP、改变电源或合成器设置，也没有运行工作区全量测试。

## 实现与复用

复用正式 daemon、现有五账号调度、存储、Unix IPC、受控阅读资源与真实 GPUI 邮箱窗口，不建立另一套邮件业务。无依赖、schema、IPC 版本变更。

- 邮箱每3秒检查同步修订、通知定位和可见状态；取消无条件 `cx.notify()`，仅状态文字变化才通知。邮件载入和用户操作仍走原有通知路径，不改变发送、草稿、同步或错误恢复语义。
- 移除生命周期中从未赋值的旧 `main` 窗口字段和无效刷新分支；抽取 `close_frontend`，正常关闭及测量结束都经过原有保存/退出前台协调，后台保持运行。
- `performance_fixture` 只接受尚不存在的绝对数据目录，最多每账号一万封合成索引，最新200封缓存小正文。创建假凭据必须同时匹配私有总线及私有根标识，不碰系统 Secret Service。
- `tools/performance_probe.py`：私有 D-Bus、私有 Secret Service、localhost TLS IMAP，运行正式 production daemon；每5秒读取进程树 PSS、累计 CPU 和五账号状态，保留周期工作。支持 IDLE 及不支持 IDLE 的轮询对照。
- `tools/cached_performance_probe.py`：五账号各一万封，通过真实 IPC 测量分页、搜索和缓存正文读取。`tools/window_performance_probe.py`：真实窗口的后台帧事件采样及连续切信/搜索/翻页/窄窗专项；确认退出前台后后台仍存活。
- `QINGMAIL_WINDOW_PERF=idle|interaction` 仅在显式设置隔离根时生效，普通启动不自动运行。帧计数收集放后台线程，避免采样器前台轮询本身造成重绘。不把 GPUI 提交完成当作显示器实际呈现反馈。

## 五账号后台预算

环境：Arch Linux、Intel Core i9-14900HX、32逻辑核、内核7.3.4-arch1-2、系统Rust1.100.0、release构建。测量期间机器仍有开发/构建等其他负载，未为测试改变系统电源策略。服务端和私有总线/密钥库是外部测试设施，不是 daemon 子进程；其开销不计入产品进程树，也不声称为实际邮件服务商兼容性。

五个 TLS IMAP 账号，空收件箱完成初始同步；前段正常，末段测试设施故障。就绪 UTC 07:41:25，稳定至少300秒后连续采样1800.067秒，每5秒一次（含端点共359条）。样本包含周期同步、IDLE重建和维护，没有挑掉高峰。UTC08:11:08私有gnome-keyring-daemon断言崩溃，D-Bus随后拉起锁定的替代服务，约1543秒开始五账号报告密钥库锁定。`budget_passed=false`；只满足时长和数值不足以通过验收。已修正探针判定，要求私有服务存活且五账号全程同步正常，防止再把退避误计为稳定预算。

| 指标 | 实测 | 预算/结论 |
| --- | --- | --- |
| 后台进程树最大PSS | 16.878 MiB | 数值≤80 MiB；稳定场景无效，不能验收 |
| 平均单核CPU | 0.46054% | 数值<0.5%；后段进入凭据退避，不能验收 |
| 采样窗 | 5分钟稳定＋30分钟采样 | 满足设计口径 |
| IDLE/账号状态 | 原始样本记录五账号独立状态、活动IDLE数与IMAP命令累计 | 最后五账号均报告密钥库锁定；不是稳定场景 |

CPU按 `(末累计CPU秒−首累计CPU秒)/实际墙钟秒×100` 计算。PSS读取 `/proc/*/smaps_rollup` 并包含后代；生产后台未生成额外子进程。IDLE当前采用约15秒有界等待后重建连接，未在本轮更改。下一轮应先定位测试密钥库崩溃，再完整重跑5＋30分钟，不拼接前段样本。

证据：[长时数据](evidence/P4-004-five-account-idle.json)、[运行日志](evidence/P4-004-five-account-idle.log)。轮询补测仅稳定5秒/采样120秒：PSS最大11.651 MiB、单核CPU0.4333%，只证明回退正常且未出现明显忙循环，**不具备长期预算资格**。见[轮询数据](evidence/P4-004-five-account-polling.json)。

## 索引与窗口专项

五账号各10,000封，共50,000封合成索引；每页只传200条（真实统一列表默认100条）。下表是IPC到业务完成的延迟，包含IPC接受等待、存储和返回；不是SQL耗时，也不是实际按键到显示器呈现延迟。

| 操作 | 次数 | P50 / P95 / 最大（ms） |
| --- | --- | --- |
| 文件夹200封分页 | 100 | 50.10 / 51.00 / 51.46 |
| 统一收件箱200封分页 | 100 | 50.17 / 51.63 / 93.71 |
| 命中搜索 | 100 | 50.23 / 51.48 / 52.22 |
| 无结果搜索 | 100 | 50.10 / 51.07 / 51.35 |
| 缓存正文及安全资源生成/释放 | 50 | 200.57 / 201.36 / 201.94 |

约50ms的量级包含既有IPC接受循环最多50ms的等待，不能把所有延迟归因于数据库。本轮没有仅为降低基准数字重写IPC。见[逐次数据](evidence/P4-004-index-latency.json)。

真实窗口专项通过：统一列表连续选30封后最终正文身份与选择一致；中文查询有结果；切到单账号收件箱200封；加载UID<9801的历史页并返回最新UID10000；窄窗实际900×760。各动作状态完成约357/101/51/51/51ms，包含25ms观察粒度；输入通过现有文本组件设置中文，**不是中文IME候选词实测**。见[窗口数据](evidence/P4-004-mailbox-interaction.json)。测试使用原生Wayland/Intel Vulkan、scale1.25、HighPower、reduce_motion=false，未绕过省电限制。

窗口启动期间树PSS约109–113 MiB，包含UI及其启动的隔离后台，不冒充纯UI常驻值。退出后确认GPUI进程消失、daemon仍可响应，再清理测试后台。没有打开系统浏览器，不据此推定浏览器成本为零。

## 空闲绘制证据与未通过项

已修复应用层3秒无条件刷新，但**不能据本轮认定整个窗口静止时不持续重绘**。同一Hyprland桌面上，稳定8秒后12秒采样出现优化前47次、优化后68次、重复1次的波动；重复样本曾与另一个测试窗口的生命周期重叠，焦点/平铺变化是干扰因素。全部保留，不选最低数字宣称优化比例。见[前](evidence/P4-004-mailbox-before.json)、[后](evidence/P4-004-mailbox-after.json)、[重复](evidence/P4-004-mailbox-repeat.json)；[最终串行复测](evidence/P4-004-mailbox-final.json)为12.041秒0次绘制/提交，说明稳定时可保持静止，但不能据单次0帧抹掉波动。最早前台采样器诱发重绘的结果已弃用，不计为产品性能证据。

P4-006收口前仍需：

- 在无鼠标/焦点/平铺变化的条件下定位剩余绘制来源，补充帧间隔和真实输入/列表体验；不把HUD推导FPS当作呈现率。
- 100/150/200%真实系统缩放，125%人工体验、跨屏/平铺、中文候选词和选区。900×760自动调整只覆盖一个窄窗尺寸。
- 真实休眠/恢复、断网/联网和网络切换、省电/平衡切换；本轮没有改变全局设置或真实网络。
- 新信、历史同步、下载、服务器草稿上传各自的非空闲峰值和恢复时间。本轮缓存读取数据不替代网络下载/草稿峰值。

这些是设计中已有验收项，不新增功能或另建性能工程；如集中验证暴露问题，修复后只补相关测试。当前不能标记P4性能与体验全部完成。

# P3-002a：独立后台与持久请求基础

日期：2026-11-17。基线：29b35cc（P3-001）。状态：本子步完成，P3-002 继续实施；尚未切换正式 GUI。

## 已实现

- `mail-daemon` 独立二进制复用已有 StorageWorker 和 SyncEngine；启动时确认数据库真正就绪，停止时先等待同步线程，再关闭存储。依赖树无 GPUI/mail-ui。
- 开发入口强制显式 `--isolated-root <绝对目录>`，关闭邮件网络，不读取正式 XDG 账号或密钥库。提供 `--status`、`--quit`；正常应用仍使用 `mail-ui`，本轮没有发布替代测试包。
- Unix socket 运行目录 0700、socket/锁 0600、同用户 peercred 校验、单实例锁、受控残留 socket 清理；拒绝符号链接、普通文件和不安全目录。退出显式释放实例锁，避免并行 fork/exec 短暂继承描述符延长锁寿命。
- NDJSON 客户端和服务复用 v1 类型与 2MiB 上限，校验版本/请求ID；固定4个控制线程、16个等待连接，每个帧绝对期限5秒，避免逐字节输入无限占用。客户端不自动重试；未知/未接入能力显式拒绝，Hello 只列实际已接入命令。
- 存储 RPC 复用账号/目录缓存查询、本账号搜索、草稿打开/新建/选择/保存/丢弃、附件元信息、发送记录及停止不确定记录等现有实现。SMTP 确认、网络、资源与会话命令仍不提供。
- schema8→9 增加 `mutation_results`：执行前持久取得请求ID与命令摘要，完成结果写盘后应答；同ID不同参数冲突，同ID已完成返回原结果。重启把未完成记录变为“不确定”，不重放业务。业务事务与结果日志之间中断时也保守返回不确定，调用者须查询结果并读回业务状态。
- 该日志是 IPC 幂等基础，不是 P3-004 的离线 IMAP 队列，也不赋予任何 SMTP 重发许可。

## 验证

`cargo fmt --all -- --check`、`cargo check --workspace --locked --offline`、`cargo test --workspace --locked --offline`、`cargo clippy --workspace --all-targets --locked --offline -- -D warnings` 通过，合计145个测试。Unix/TCP socket 测试在获准环境运行，不连接真实邮箱。

新增9个测试：2个存储幂等/迁移测试、2个存储RPC测试、5个独立进程/端点测试。覆盖 schema8 升级保留账号/草稿及私有备份、未完成请求恢复为不确定、保存版本冲突、无响应后查询/重放不重复建草稿、第二 daemon 拒绝、真实进程PID隔离、SIGKILL后残留socket恢复及已确认草稿保留、不兼容版本/未知字段/断开客户端无副作用、未实现发送拒绝、路径与权限边界。

首轮新进程测试发现临时目录默认权限不符合0700与并行子进程短暂继承锁的问题，分别通过显式私有测试目录和端点退出解锁修复，完整门禁已重新通过。没有运行 GUI E2E：生产 GUI 尚未切换，集中原生验收保留在拆分完成后。

# P4-003 自启动与桌面生命周期

日期：2026-11-18。状态：实现及相关自动测试通过；真实登录/注销、设置页视觉与桌面整体交互留 P4-006。本轮不访问真实账号、密钥库、用户自启动配置，不发送邮件，不运行工作区全量测试。

## 实现与复用

- 默认关闭；用户在现有 M3E 设置页明确开启后，后台创建 `$XDG_CONFIG_HOME/autostart/org.qingmail.QingMail.desktop`（未设置时使用 `~/.config/autostart/`）。只执行当前后台的规范化绝对路径及 `--production`，不打开主窗口，不注册系统服务或修改 Hyprland 配置。Exec 按 Desktop Entry 的字符串和参数两层转义；TryExec 使用相同路径。
- 设置页分别显示实际文件状态与失败原因，提供开启/关闭、重新应用当前选择和刷新。写入期间禁止重复提交；修订冲突保留原界面并要求刷新。关闭开关不停止当前后台；保存并退出不清除下次登录选择。
- 存储线程先持久化意图，再处理外部文件，成功后清除 pending。文件与数据库不假装原子事务；写入、权限或同步失败保留 pending，刷新和后台重启可恢复。普通已完成意图不会在刷新时重建被用户删除或改写的文件。程序目录移动后显示失效，须明确重新开启确认新位置。
- 受管文件要求完整模板和 QingMail 管理标记；同名非受管文件、符号链接、非普通文件、外部可写目录/条目不覆盖或删除。受管文件用同目录独占临时文件、文件同步、原子 rename 和目录同步更新；首次创建使用 NOREPLACE。关闭仅删除检查为受管的条目。隔离后台拒绝自启动接口，不能通过前台传任意路径或命令。
- 复用现有后台单实例锁、前台会话、全部编辑窗口保存协调、托盘打开/退出，不重写生命周期。已有后台时第二实例仍被明确拒绝，原后台继续；保存失败保留会话，不能假装退出成功。设置页说明无可见托盘时再次打开应用可返回前台。
- 正式启动在打开数据库之前核对会话 D-Bus 与显示环境，并继续要求绝对 XDG_RUNTIME_DIR；缺失则明确报未就绪，不回退到其他运行/数据目录。实际通知服务或托盘宿主不可用仍按现有降级状态反馈，不把环境变量存在当作服务可用。

## 数据和协议

schema18→19仅新增 `autostart_intent`，保存修订号、期望值、pending和受控后台路径；沿用迁移前私有备份、事务升级及未来版本拒绝。保留账号、草稿、缓存、发送任务和通知设置。旧迁移夹具相应移除新增表，以真实模拟历史版本。

新增独立 `AutostartSettings` / `SetAutostart` 命令与独立结果 DTO，不修改已有严格 DTO或激活枚举，因此维持 IPC v2。前台握手要求两个自启动能力；旧后台缺少能力、新后台的能力对旧严格枚举不可解码，均在 AttachUi 和写操作前拒绝混配。仍须先保存并退出旧前后台，再配套更新两个程序；P4-002 的旧程序不能读 schema19。

写入沿用持久请求 ID及 MutationResult：响应丢失查询原结果，不重放原写。原结果表示该请求当时的状态，之后刷新核对实际文件。进程在结果完成前中断时保留不确定请求，待协调意图恢复；不据此恢复或重放SMTP。

## 使用与未测边界

启动项已就绪不等于真实登录已验证。会话必须执行 XDG autostart；裸 Hyprland 配置未必自动执行，本轮不静默注入 compositor 配置或另建自启动服务。真实登录、休眠/注销、托盘可见性及设置GUI在 P4-006集中核验。用户未开启前不产生启动项。

程序位置失效时 TryExec 避免失效启动；移动/重新安装后需在设置中重新应用。正常卸载不主动清除个人配置；需要取消时在设置关闭，或在确认受管文件后手动清理上述用户启动项。安装布局、PKGBUILD和卸载验证属于P4-005。

未扩展OAuth、通知规则、发送恢复策略或整套GUI重设计。下一步为P4-004性能与体验验证，不能据本轮宣称性能预算达成。

# P2-003 · 后台存储线程与原生多草稿

- 日期：2026-11-16
- 状态：实现与自动验证完成，新增多草稿交互待操作者验收。
- 依据：P1 已确认设计、P2-001/002、ADR-0003/0005/0006。

## 1. 本轮实现

mail-daemon 新增事件驱动 storage 工作线程，独占创建/使用/销毁 Store；16 项有界命令队列，支持打开、保存、新建、枚举、选择本地草稿。无存储空闲定时器；请求到达才工作。UI 使用 try_send，不在 listener 中等待数据库；响应在 GPUI 后台 future 等待后回到实体更新。响应接收方销毁不阻断已接受请求或后续命令。停止线程时依队列顺序处理已接受请求再退出。

原生编辑窗口替换 DraftStore 单槽：默认 XDG data/qingmail，后台 SQLite+不可变正文对象保存。保持现有受控格式与版本规则，防止迟到确认把新改动标记成已保存。关窗和保存并退出必须等最后版本确认。初始加载失败保持只读，可重试或关闭；保存失败保留窗口和最后确认版本，停止自动反复写入，提供“重试 / 立即保存”。

新增“新建本地草稿”和稳定 ID 草稿按钮，可切换多份草稿；未保存时先触发保存并提示，再次操作才切换，避免丢改动。草稿新建、选择、正文保存都经工作线程；重启记忆所选草稿。当前工具栏是开发验收入口，后续产品页将使用 P1 账号文件夹树/草稿列表，不把 ID 按钮固化成正式产品设计。

## 2. 本地草稿空间与迁移

schema v3 为 accounts 加 kind=remote/local 和唯一 local 空间，增加 local_editor 记录选中草稿。local 使用明确“本地草稿”身份与不可用连接占位，不包含凭据；account()/accounts() 只返回 remote。enqueue_draft 要求可用远程账号，因此 local 不能直接创建发送任务，不伪装邮箱已添加成功。未来账号配置后仍需明确选择发信账号。

v1/v2 升级先备份，事务升级至 v3。新增测试从真实 v2 布局恢复，原远程账号和草稿正文不变。v1 升级与原有发送六状态测试继续通过。

旧 `target/p0-editor/draft.json` 保留原样，不自动导入或删除；当前 P0 技术草稿若需保留，可在旧源读取/复制后导入，尚未交付一键迁移。验证模式继续使用 QINGMAIL_P0_DRAFT_ROOT 作为可信隔离根，正式数据位于其 p2-data 下，输入诊断位于 p2-editor-probe 下。默认应用不以 target 为正式存储。

## 4. 人工验收与限制

待验证：在第一份草稿输入、保存；新建第二份并输入不同文字；切回第一份检查内容与格式；关闭编辑窗口从主窗重开确认所选草稿；输入后立即关窗再重开检查最新内容。验收使用隔离持久目录 target/p2-003-acceptance，测试后资料可保留供复验。

本轮没有收件人/主题/附件产品输入区、草稿删除/另存为恢复对话框、损坏草稿选择性恢复、正式账号登录或协议发送。工作线程枚举暂读取本地草稿正文，没有虚拟化/分页，大量草稿需后续列表实现；孤立对象回收继续未完成。现有主窗合成计数器和生命周期150ms轮询仍保留，不能把存储线程事件驱动扩展成整应用已达空闲资源预算。

下一轮在本轮交互验收后推进密钥库边界、通用账号检查与原生账号/文件夹页面；完整 MIME 冻结、真实 SMTP/IMAP、编辑器 P0 缺口和 P2 总退出验收仍未完成。

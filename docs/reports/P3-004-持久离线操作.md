# P3-004：持久离线操作

日期：2026-11-17。基线：P3-003 `266af1e`。状态：实现与隔离自动测试通过；真实断网/多账号兼容、最终GUI集中验收仍留P3-007。

## 1. 实现与复用

正式邮件页的已读、星标、归档和删除改用既有协议 `EnqueueOperation`。归档/删除解析为同账号文件夹移动，删除不使用全局EXPUNGE。单目录和统一收件箱共用入队适配；跨账号批操作继续分别分组，部分失败分别报告。点击后只有入队事务提交才反馈“待同步”；控制响应丢失不自动以新请求重放，状态入口可查看已持久记录。

新增schema12 `mail_operations`，保存完整邮件定位、操作、状态、错误、尝试次数、重试时间与只读核对请求。每封操作和请求幂等结果同事务提交，批内校验失败回滚全部；同请求ID重查只返回原结果，异参数拒绝。schema11→12沿用迁移前私有备份、顺序事务和未来版本拒绝；既有账号、凭据引用、草稿、对象、发送任务保持。

服务器确认状态仍保存在原 `folder_messages`；新增 `visible_folder_messages` 视图叠加本地意图。最新标记按字段显示，待处理移动在源列表隐藏；失败、冲突和不确定仍保留意图，明确保留服务器状态后才释放。单目录、统一收件箱及本地搜索使用相同投影；后台普通同步只更新服务器索引，不能抹掉待处理意图。没有另建邮件索引或修改SMTP状态机。

## 2. 执行与恢复

后台新增独立IMAP操作协调器，复用StorageWorker、network_gate、mail-service的TLS认证/标记/移动。最多两个工作循环，共用P3-003的主动IMAP上限；每账号严格按队列顺序，失败/冲突/不确定阻止该账号后续越过，其他账号继续。暂停账号和全局暂停均阻止新的自动执行，已在途网络请求不强制终止。

执行前核对远端UIDVALIDITY、UID是否仍存在；标记执行后读回核验。认证失败持久暂停对应账号；UIDVALIDITY改变或源UID消失进入冲突。临时DNS/连接/超时在安全边界内间隔60秒、最多3次尝试，之后失败可手动重试；其他明确失败显示原因。

移动网络适配增加“可能已产生副作用”的边界信息：认证/选择前失败可安全尝试；MOVE命令写入前即置位，写入或响应丢失后保守进入不确定。MOVE退化COPY后的非完整确认同样不自动重放。重启时在途标记恢复Pending，在途移动恢复Uncertain，不因socket重连或缺少响应推断未执行。

`ResolveOperation::Reconcile`仅安排只读源UID/标记核对，不重放MOVE/COPY。标记与意图一致可确认完成；移动源仍存在或已消失，都不足以证明目标副本归属，继续不确定并显示核对结果。用户查看源/目标后可两步确认 `KeepServer`，明确放弃本地意图，释放覆盖层并继续队列。这不宣称已自动证明远端移动成功，也不会“重试”不确定移动。

旧Business Flags/Move入口明确拒绝，正式UI修改统一走持久队列。SMTP发送协调器不受此队列驱动，网络恢复、重启和重连不会发送离线草稿。

## 3. 界面与有界行为

沿用当前M3E邮件布局，增加“待同步操作”入口及数量/问题汇总；邮件行显示待同步、执行中、失败、冲突或不确定。操作窗口显示完整账号定位、状态、操作与原因，支持刷新、失败重试、只读核对及两步确认保留服务器状态，3秒刷新。后台会话轮询读取操作状态，不在GPUI线程等待网络。

当前未完成操作全局上限200封；列表优先显示所有待处理记录，以最近完成记录补足200条，防止失败被历史记录挤出。超过上限拒绝新事务，提示先处理现有任务；不静默丢弃旧操作。已完成操作保留用于恢复和审计。当前标记不合并，保留逐条顺序与字段投影；没有新增通用移动/删除撤销。

正文/附件对象没有引入淘汰或新清理；未完成操作对应的资源引用在后续缓存实现中必须受保护。本轮不实现按需MIME、服务器草稿或磁盘缓存预算。

# P2-012 · 发送任务入口与受控重发

> 历史轮次记录：下文“当前/尚未”均指本轮结束时；最新实现与待办以 [P2 当前状态与剩余工作](../P2-当前状态与剩余工作.md) 为准。

- 日期：2026-11-16
- 状态：实现、110 个 Rust 测试与构建门禁通过；未使用真实账号，重发/停止的原生点击未单独验收。

## 1. 本轮范围

补齐发送闭环 A 项剩余的产品入口与受控操作：

1. **发送任务入口**：跨草稿查看当前账号的全部发送任务（有界 200 条），展示冻结主题/发件人/收件人/时间、状态与固定诊断原因、副本位置。
2. **受控重发**：仅对 `failed` / `uncertain` 任务，由用户在任务入口二次确认后，用原冻结内容创建一个新任务并提交；旧记录保留。
3. **停止处理**：`uncertain` 任务可标记"停止处理"，不宣称撤回，不自动重试。
4. **只重试副本**：任务入口复用 P2-011 的 `retry_copy`，不经过 SMTP。
5. **失败后修改再发送**：明确失败的历史允许修改草稿后重新提交；相同版本、`uncertain`、`sent`、`copy_pending` 仍阻断。

不新增 schema 版本、不新增依赖、不改变 SMTP/IMAP 协议层。

## 2. 实现

### 2.1 存储与任务视图

`SendTask` 增加冻结的 `sender`、`recipients`（含主题）与 `created_at`，任务入口无需重建 MIME 即可展示。`Store::task_list` 按创建时间倒序返回至多 200 条；`StorageClient` 增加 `tasks`、`stop_uncertain`，以及重发所需的 `resend`、`begin_task`、`cancel_pending`。

`resend` 在同一存储请求内完成：校验旧任务状态 → `resend_task(UserConfirmed)` 创建唯一新任务 → 读取冻结快照与 SMTP 配置；任一失败则取消新任务，避免留下永远 `pending` 的记录。取得 `Sending` 许可仍是独立请求，且只有 MIME 重建成功后才调用。

### 2.2 协调器

- 抽出 `run_submission`：一次 SMTP 提交 + 结果写盘 + 必要的副本保存；`confirm` 与 `resend` 共用，避免两套提交路径。
- 新增 `SendCoordinator::resend`：只由任务入口的确认按钮触发；先取密钥（密钥不可用不创建新任务），再创建/冻结/提交；仍受全局单任务互斥和退出等待约束。
- 重发的新任务使用新任务 ID，因此 Message-ID 也是新的；旧任务与旧 Message-ID 记录保留。

### 2.3 发送门控

`review()` 从"有任何发送记录就拒绝"改为按状态区分：

| 历史状态 | 同一版本 | 修改后的新版本 |
| --- | --- | --- |
| 无记录 | 允许 | 允许 |
| 全部 `failed` | 拒绝（请用任务入口重发） | 允许（作为新任务提交） |
| 含 `uncertain` | 拒绝 | 拒绝（先处理原任务） |
| 含 `sent` / `copy_pending` / `pending` / `sending` | 拒绝 | 拒绝 |

这样"修改后重发"不会绕过不确定/已发送的保护，也不会把失败任务当成可重复使用的提交许可。

### 2.4 界面

- 新增 `send_tasks` 窗口：任务列表、刷新、重试副本、重发（行内二次确认，`uncertain` 明确提示可能重复）、停止处理、副本位置。
- 状态与诊断文案抽到 `send_labels`，写信窗口与任务窗口共用，未知诊断代码不展示服务器原文。
- 写信窗口新增"发送任务…"入口；有失败历史时提示"修改后重新检查，或到发送任务重发"；发送按钮只在存在非 `failed` 任务时禁用。
- 新增 `--send-tasks` 与 `Command::SendTasks`，窗口经 `Lifecycle` 复用/注册。

## 4. 限制与下一轮

- `uncertain` 重发仍是用户明确决定；界面展示"可能重复"警告，但不提供查看已发送副本正文的跳转（只显示副本文件夹/UID）。
- 任务列表固定最多 200 条、无筛选；旧任务长期保留，清理策略随 P3 缓存/对象回收。
- DNS、整次 SMTP 与整次副本保存仍无独立总期限；本轮未做强制取消。
- "修改后重发"只覆盖明确失败；不确定任务必须先重发或停止，不能通过改草稿绕过。
- 真实 Secret Service + 通用账号的贯通验收仍未进行。

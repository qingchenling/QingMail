## 1. 本轮范围

完成 D 项：

1. 修改已有账号的连接配置，重新检查后更新同一账号（ID 与本地缓存/草稿不变）。
2. 更新凭据/同账号重新认证：重新输入密码、检查通过后覆盖 Secret Service 中的同一账号条目。
3. 本地移除账号：先统计影响（缓存邮件、草稿、发送任务、待处理任务、本地对象字节），明确确认后删除本地账号数据；不删除远端邮件。
4. 密钥库不可用/锁定的恢复入口接到同一账号：错误持续显示，解锁后可直接重试更新，不需要删除再添加。

不新增 OAuth、不新增全盘密钥扫描、不做多账号管理。

## 2. 实现

### 2.1 存储与移除顺序

- `Store::update_account`：只更新 `accounts` 行，账号 ID 不变；本地文件夹、草稿、发送任务、缓存均保留。
- `Store::account_impact`：统计 `folder_messages`、`drafts`、`send_tasks`（含 `pending/sending/copy_pending`）与对象总字节。
- `Store::remove_account`：单事务按外键顺序删除任务附件、发送任务、草稿附件、编辑选择、草稿、正文缓存、文件夹关联、文件夹、邮件头、附件、对象、远端目录、目录同步与账号；提交成功后再删除对象文件。提交失败不会先丢文件；远端邮件从未被访问。
- 密钥库条目在本地账号删除后尝试删除；若删除失败，返回“账号已移除但密钥库条目可能仍在”的明确提示，不自动扫描全盘。

### 2.2 协调与界面

- 新增 `UpdateAccount` / `AccountImpact` / `RemoveAccount` 存储请求；更新先写 Secret Service，再更新配置；配置失败时明确提示“凭据已更新但配置保存失败”。
- 账号窗口支持：
  - 展开账号 → “编辑配置”：预填名称/地址/服务器/端口/用户名，密码留空，必须重新输入并检查通过后才能更新；
  - “检查连接”不再因已有账号而拒绝，检查通过后按钮变为“更新账号”；
  - “移除账号”：先显示影响统计，确认后移除；有在途发送时拒绝移除，存在待处理任务时错误色提示；
  - 现有“检查密钥库”与错误文案保留，更新/保存会重试密钥库，不需要删除账号再添加。

### 2.3 安全与边界

- 移除只影响本地：不发送任何 IMAP/SMTP 删除命令，不连接远端。
- 在途发送（`SendCoordinator.active()`）期间禁止移除，避免发送结果写盘时账号已被删除。
- 移除会删除发送任务记录（包括不确定/副本待保存），确认面板明确提示；这是“本地移除”的既定影响，不宣称撤回或删除远端邮件。
- 单账号限制不变：添加路径仍只允许一个远程账号；移除后可重新添加。

## 4. 限制与下一轮

- 更新配置要求重新输入密码；不从密钥库静默读取旧密码代填。
- 移除后没有“撤销”；用户需要重新添加账号。
- 移除时如果密钥库删除失败，会留下孤立凭据项；按既定范围不做全盘扫描，提示用户处理。
- 真实 Secret Service 保存/覆盖/删除、认证失效恢复与本地移除的端到端行为仍需集中验收。

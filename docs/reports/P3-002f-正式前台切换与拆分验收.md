# P3-002f：正式前台切换与拆分验收

日期：2026-11-17。承接002a～e，完成P3-002单账号进程拆分实现。验证结论限于下述证据，未访问真实邮箱、未发送真实邮件、未以真实密码进行Secret Service跨进程实测。

## 1. 实现范围

正式 `mail-ui` 连接/启动同目录 `mail-daemon --production`，Hello能力检查后附加前台会话并取快照。daemon持有唯一SQLite写者、同步、发送、邮件网络、解析/安全副本、账号工作流和托盘。前台仍复用既有StorageClient异步接口与M3E控件，实际走IPC；密码仅输入后写Secret Service临时项，IPC传引用。旧进程内实现仅供显式隔离诊断，不再是正式入口。

主窗关闭先协调所有编辑窗口保存，成功后Detach并退出GPUI；保存失败保留窗口。托盘在daemon，Open激活现有前台或启动新前台，Quit协调保存并退出两进程。无托盘宿主时状态说明重新启动及--quit。第二实例合并同步并激活现有窗口。心跳失效显示错误；后台重新启动后UI重新附加、刷新epoch/快照，不重放发送或其他写操作。崩溃前台的租约15秒过期，过期不等于保存成功。

邮件目录/历史同步、标记、移动、正文、安全浏览器副本、明确同意的远程图片、发送任务内容及账号移除迁入daemon的有界业务工作线程，复用mail-service、mail-content及原发送状态机。邮件四元定位与文件夹名/epoch共同核对。移动结果不确定不盲目重放。账号移除、提交与发送启动/退出协调检查串行化，忙时明确拒绝；退出准备接受后不再接收新业务。

## 2. 协议和资源边界

保留v1、同UID、0700/0600、2MiB NDJSON、64KiB二进制分块及绝对超时。临时传输资源扩为1024项/总预留64MiB/空闲10分钟，兼容合法MIME部件数；不代表磁盘缓存预算。正文解析/清理在daemon，UI只构造已清理的阅读树与受限图片。受控display handle最多4份，浏览器URL仅由后台生成，不接受任意客户端路径。IPC不传整封MIME JSON。

大草稿通过CreateStorageRequest/StorageRequest与Reply::Encoded资源传输，请求封包最大16MiB，内层仅接受既有存储命令且ID一致；禁止嵌套网络、退出或任意路径操作。持久结果同步提升至16MiB上限，避免“保存成功但结果永久无法确认”。原草稿32KiB正文、8MiB序列化和发送附件限制保持不变。

DraftPage每页1份草稿、TaskPage每页32项，以ID游标查询；前台为复用现有列表聚合页面，不声称大型列表性能已达标。原兼容Drafts/Tasks命令仍可用，但超过封包上限明确报错；正式适配已使用分页。业务结果保留64条，淘汰最旧已完成结果，不淘汰活动任务。

schema10不变，沿用schema8→9→10迁移、私有备份、对象/账号/草稿/任务/凭据关联与未来版本拒绝。没有加入离线操作队列、多账号、BODYSTRUCTURE、服务器草稿或缓存淘汰。

# 发送成功确认界面

日期：2026-11-20

## 行为

- 写信工作区收到已发送或副本待保存结果后关闭，邮件详情栏替换为发送确认页面；左侧文件夹树和中间列表保持主窗口布局。
- 复用已有发件箱识别方法，自动切换到当前账号的“已发送”文件夹。只有服务器确认的副本位置与缓存的账号、文件夹、UIDVALIDITY、UID均匹配时选中该行；不按主题或发件人猜测。副本无UID或没有缓存时仍展示确认页与本地发送记录。
- 显示收件人、主题、提交时间及最多600字的纯文本摘要，超过时加省略号；长内容与窄窗支持滚动，配色、按钮及入场动效复用现有M3E组件并遵循减少动态设置。摘要来自冻结发送快照，不重新下载服务器正文，也不加载远程图片。
- “显示发送状态”展开当前邮件的状态，复用后台状态刷新；“查看已发送邮件”打开既有本地发送记录阅读器；“返回邮箱”回到该账号收件箱；“继续写信”打开同账号新草稿。
- 保留截图中的“撤回邮件”入口。普通SMTP接受邮件后无法保证撤回，因此点击只说明限制和建议联系收件人，不会删除已发送副本或声称撤回成功。联系人自动保存及其提示均不实现。
- 已发送且副本保存失败时，页面显示“发件箱副本待保存”，并提醒勿重复发送；成功保存后状态与底部提示随后台快照更新。未启用保存副本时明确显示本地记录，不宣称已保存到服务器。
- 修复原先本地发送记录读取仍调用进程拆分前内部接口的问题。确认摘要与完整记录统一复用`TaskContent`业务接口、受控阅读资源和原有Reader；后台从冻结快照生成内容，不要求凭据或联网；不传输整份快照JSON，也不改数据库或IPC版本。切换账号或页面后丢弃迟到的读取结果。

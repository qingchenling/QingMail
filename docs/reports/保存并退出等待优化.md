# 保存并退出等待优化

日期：2026-11-19。

## 问题与调整

此前只取消正文读取，遗漏了两条退出等待路径：默认自动加载的远程图片被当作必须完成的业务；IMAP IDLE 长连接仍等待最长约15秒的响应期限。另外，后台按顺序停止线程，等待前一个任务时其他任务仍可能继续开始网络工作。

- 远程图片和正文统一归入可取消读取，注册同一任务取消信号。图片使用可取消的异步HTTP读取：DNS、等待响应和分块读取由25毫秒检查取消，取消后关闭运行时连接；系统DNS工作不阻塞运行时收尾。复用锁文件已有Tokio 1.54.1，不升级其他依赖。
- 保留图片每跳DNS校验/固定地址、禁止私网/代理/HTTPS降级、类型及资源上限。取消不发布半成品阅读资源，也不把未完成的图片标为已加载。
- 已认证的IDLE只读连接由取消监视器关闭socket，包括服务端只返回半帧的情况，不等待15秒期限，也不复用半帧连接。
- 退出最终确认后，先向草稿同步、附件、离线队列、正文/图片和收信调度发出停止信号，再逐一等待收尾，避免叠加新网络工作。前台保存失败仍可取消退出，不提前停止后台。
- 本地草稿可靠写盘、账号保存和在途SMTP仍须完成确认；未改变发送状态机，不新增自动重发。

## 本轮验证

只运行相关测试，未运行全量测试：

- `mail-content`远程图片4项：等待响应和正文中断、取消后内容保留、私网限制及部分失败重试。模拟卡住请求两种情况约59–62毫秒返回，服务端观察到连接关闭。
- `mail-service` IDLE 4项：正常消息、不支持回退、静默/半帧超时，以及静默/半帧取消。取消场景约43–67毫秒结束，包含本机TLS交互，不等待15秒。
- `mail-daemon`业务退出2项：正文/图片可取消，写业务仍阻止退出，取消后不发布资源。
- 独立进程会话/保存失败回归1项：失败时后台保留；确认退出约60毫秒，重启后草稿仍在。
- 原生Wayland隔离窗口：经相同退出协议确认，前台与后台全部退出约766.5毫秒。使用临时空账号数据，无真实邮箱访问、发送或物理菜单点击。可再生证据：`dist/verification/shutdown-latency.json` / `.log`。
- fmt、前后台check、相关四crate的all-targets Clippy（`-D warnings`）通过；调试版UI与daemon均已构建，未重新打包。

## 测量边界

这些结果只对应本机隔离场景，不等于真实账号任意状态都能在一秒内退出。正在执行的云端草稿写入、离线操作和SMTP提交仍等待安全收尾；IDLE连接建立/认证及其他既有阻塞网络调用保留原有超时。未对用户当前真实账号执行计时或收发操作。

测试新版前需先用旧实例的“保存并退出”结束两个进程，再运行 `./target/debug/mail-ui`；仅重新打开前台会继续连接旧后台。

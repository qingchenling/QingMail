# P3-005 按需正文与附件下载

日期：2026-11-17。基线：P3-004 `19bdfea`。本轮实现资源分段获取，不扩展到服务器草稿或缓存预算。

## 1. 实际交付

- 新邮件先取 RFC822.SIZE、头部与 BODYSTRUCTURE，仅获取选中的纯文本/HTML 正文与引用的唯一 CID 图片。含大附件的邮件可以先读小正文；附件元信息不会触发附件正文下载。
- `mail-core::MimeStructure/MimePart` 定义有界清单；`mail-service::parts` 复用既有登录、TLS、IMAP 响应解析、EXAMINE 与 UIDVALIDITY 校验，按 section 发出≤64KiB部分请求，增量解码 base64/quoted-printable。
- `mail-content::parse_sections` 复用既有 MIME、HTML 清理、图片校验和浏览器副本。派生阅读 MIME 不是原邮件，不可用于 P3-006 直接覆盖服务器草稿原件。
- schema12→13 顺序迁移，新增 `message_structures`、`part_resources`。账号/文件夹/UIDVALIDITY/UID/section 共同定位，清单不可变；复用 objects 不可变写入与完整性校验，记录访问时间，移除账号清理引用。
- 后台两个附件工作线程复用主动 IMAP 限流和同账号串行约束。下载进入私有、立即 unlink 的临时文件；完整解码、同步、关联后才发布 Ready。取消、失败、崩溃不留下可误认为完整缓存的部分对象。
- IPC 增补 ResourceStatus/DownloadInfo，DownloadAttachment 显式启动，ReadResource 只读 Ready。opaque ID不传任意路径；附件文件通过64KiB二进制块读取，不受内存型资源64MiB预留限制，不把大附件装入JSON或GPUI内存。
- 阅读器显示元信息、下载状态/进度与取消；选好保存位置后才启动。下载完成后分块写同目录私有临时文件，再原子发布为最终文件，不覆盖已有文件或自动打开。正常失败/取消删除导出临时文件。
- 切信可取消旧阅读任务；有界请求结束后停止，不把旧结果显示到新邮件。下载重试采用新代令牌，取消旧代不能覆盖新代结果。

## 2. 参数与限制

| 项目 | 本轮边界 |
| --- | --- |
| 结构 | 头部≤64KiB，最多256叶节点/12层；数字section路径有界且唯一 |
| 正文/CID | 每段正文512KiB，每张CID2MiB、最多32张；选中解码资源合计≤5MiB，派生MIME≤8MiB |
| 接收附件 | 单附件解码≤1GiB，编码≤2GiB；发件25MiB/32个限制不变 |
| 下载状态 | 进度为编码网络字节，Ready资源大小为解码字节；取消在有界网络请求边界生效；重试从头获取 |
| 临时资源 | 最多1024项，空闲10分钟失效；过期取消在途下载，不删除已完成磁盘缓存 |
| 兼容路径 | 旧完整MIME缓存继续离线阅读；结构异常只在独立核实整封≤8MiB时有提示完整下载，大邮件返回可恢复错误 |

内嵌 message/rfc822 作为不透明附件；带 attachment disposition 的 multipart 保守视为不支持结构，走上述受限回退，不把附件内部正文提升为当前邮件正文。当前选择第一份非附件 plain/html；CID按正文直接引用匹配。复杂结构、替代正文选择与服务商差异仍需阶段收口兼容验证。

本轮只接入缓存关联与访问时间，**未实现 P3-007 的默认1GiB磁盘预算、淘汰与完整保护策略**。附件完整性校验使用流式SHA256；大缓存校验的性能未作专项结论。导出过程中前台强制崩溃可能留下隐藏 `.partial` 文件，最终文件不会被标记为完成。

## 3. 相关验证

遵循用户最新要求，本轮只运行受影响的测试；不运行工作区全量测试、不重复整套原生GUI验收。fmt、workspace all-targets check、clippy（-D warnings）通过。

本机TLS/Unix socket测试需要在允许本机监听的环境运行；首次受限监听失败后按相同过滤器重跑通过。没有使用真实账号、真实Secret Service凭据或发送真实邮件。隔离跨进程测试及TLS假服务器不等于真实服务商端到端验收。

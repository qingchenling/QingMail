3. **收件人字段**：收件人/抄送/密送 chips（完整地址、可移除）；Cc/Bcc 默认折叠，按需展开。

## 2. 实现

### 2.1 本地搜索

- schema v8：`messages.has_attachments` 可为空；阅读正文成功后由 UI 调用 `mark_attachments` 记录附件数量（失败不影响阅读）。
- `Store::search` 只查询 SQLite：主题/发件人 `LIKE`（转义 `%`、`_`、`\`）、可选文件夹范围、可选“有附件”，按邮件日期倒序，最多 200 条，返回命中邮件的文件夹与四元组定位。
- 搜索不访问网络；未下载正文的邮件不会被“有附件”命中，界面持续提示“仅覆盖已缓存索引；附件筛选只统计已下载正文”。
- 邮箱窗口新增关键词/发件人输入、当前文件夹/整个账号切换、有附件开关、搜索与清除；结果列表可打开正文（未缓存时按该文件夹与 UID 下载），清除后恢复之前的文件夹分页与选中项。
- 搜索使用独立的命中列表与选中索引，不伪装成当前文件夹缓存；切换文件夹会退出搜索。

### 2.2 正式入口

- `lifecycle::open_main` 改为打开邮件主界面；默认启动、再次启动、托盘“打开”都进入邮件窗口，不再进入 P0 合成首页。
- P0 首页保留为 `--home-demo` 显式诊断窗口（主题与动效验证仍可复现），不进入正常产品路径。
- 邮件窗口左侧新增“账号管理”“发送任务”；写信入口保留。账号文件夹树、左侧直角与现有列表/详情布局沿用。
- 独立技术窗口仍保留：账号、发送任务、阅读、写信。它们从主界面进入，不再需要命令行参数才能使用。

### 2.3 收件人字段

- 收件人/抄送/密送下方显示解析出的地址 chips（显示完整地址，点击 × 从字段移除）。
- Cc/Bcc 默认折叠；已有 Cc/Bcc 的草稿恢复时自动展开；可在写信窗口切换显示。
- 不改变字段仍是纯文本编辑与既有校验/发送快照。

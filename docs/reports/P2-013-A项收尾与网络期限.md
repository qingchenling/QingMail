# P2-013 · A 项收尾：副本查看与网络期限

> 历史轮次记录：下文“当前/尚未”均指本轮结束时；最新实现与待办以 [P2 当前状态与剩余工作](../P2-当前状态与剩余工作.md) 为准。

- 日期：2026-11-16
- 状态：实现、112 个 Rust 测试与构建门禁通过；真实账号与原生点击仍未验收。

## 1. 本轮范围

完成发送闭环 A 项最后两件：

1. **从任务查看内容/已保存副本**：任务入口新增“查看内容/查看副本”。副本有 UID 时从服务器已发送文件夹读取；读取失败或没有 UID 时退回冻结快照——两者是同一份 MIME，因为 APPEND 的字节由同一快照确定性重建。
2. **网络等待期限**：DNS 解析、整次 SMTP 提交、副本定位/查重阶段增加独立期限；超时按“是否已发出正文”区分明确失败与结果不确定，不做强制断开，不把不确定误报为未发送。

不新增 schema、不新增依赖、不改变状态机。

## 2. 实现

### 2.1 副本内容查看

- 新增 `StorageClient::task_snapshot`，按任务读取冻结快照。
- 任务窗口的“查看副本/查看内容”：`sent` 且有 UID 时用 `sync::message` 从 `copy_folder`/`copy_uidvalidity`/`copy_uid` 读取服务器副本；失败则显示“服务器副本读取失败：…；已显示本地冻结内容”。无 UID（服务器不支持 APPENDUID）或非 `sent` 任务直接使用冻结快照。
- 两种来源都经 `outgoing::prepare` 重建/校验，再交给 `mail_content::parse` 与既有阅读窗口，不新增阅读组件。
- 详情仍显示副本文件夹、UIDVALIDITY 与 UID；本轮不写入正文缓存，也不改变远端已读状态。

### 2.2 DNS 与 SMTP 期限

- `accounts::resolve_bounded`：DNS 解析放在独立线程，调用方最多等待 10 秒；超时返回连接失败，解析线程之后即使结束也不会产生网络提交。IMAP 连接与 SMTP 提交都使用它。
- SMTP 先解析，再把 IP 交给 lettre 逐地址尝试（最多 8 个）；TLS 域名仍来自 `TlsParameters`，证书校验与 SNI 不变。
- `outgoing::deliver` 增加 180 秒总期限：连接、认证、`MAIL`、`RCPT`、`DATA` 前都检查剩余时间；`354` 之后到发送正文字节前期限用尽仍是明确失败。正文提交中的超时/断线维持原有保守分类：结果不确定，不自动重发。
- 每次阶段切换都把 socket 超时设为剩余期限，避免单个命令无限等待。

### 2.3 副本保存期限

- `sent::save_copy` 增加 60 秒控制阶段期限：`LIST`、`EXAMINE`、查重、`APPEND` 命令前检查并重设读取预算。
- 正文字节发出后单独给 30–60 秒有界响应窗口；该阶段超时只能标为 `copy_result_unknown`，重试前仍先按 Message-ID 查重。
- `APPEND` 前的任何超时/断线都是明确未保存；不会因为期限把“可能已保存”写成失败。

### 2.4 退出反馈

退出等待发送线程时，主窗口状态改为“网络阶段已有期限”。应用仍不强制中断在途网络：强制断开会把“可能已投递”变成错误结论，违背 ADR-0005。

## 3. 验证

## 4. 残余与边界

- DNS 解析线程超时后可能继续运行到系统解析结束；它不持有连接，不产生提交。
- 单个正在阻塞的 socket 读仍受系统/套接字超时约束（5 秒级）；期限在阻塞返回后立即生效。慢速上行发送大附件的时间本身不设硬上限，但控制阶段与响应窗口有界。
- 从任务查看副本时，服务器副本按需读取、不入缓存；离线或没有 UID 时显示冻结快照内容。
- 真实 Secret Service + 通用账号的贯通验收仍未进行；A 项的产品入口和期限已补齐，但不等于真实账号闭环通过。

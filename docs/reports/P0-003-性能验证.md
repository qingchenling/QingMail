## 2. 交接实测与解释

下表来源为操作者提供的 2026-11-16 会话交接，不是本次重新测量。
没有记录的精确数值不补推。

| 对比项 | 已有观测 | 结论与边界 |
| --- | --- | --- |
| debug 构建 | HUD FRAME 约 20ms，headline 约 46fps | 未优化构建明显增加绘制耗时；约数不要求互为精确倒数 |
| release 构建 | HUD headline 达到 240fps | 绘制能力推导值达到面板上限；不能证明动画实际按 240Hz 呈现 |
| NVIDIA 渲染 → Intel 合成 | 前期只有 NVIDIA ICD，存在跨 GPU 路径；未保留同条件定量数据 | 尚不能量化跨 GPU 额外成本，也不能认定它是卡顿根因 |
| 强制 Intel 渲染 | 安装 Intel ICD 后已运行；release headline 240fps，交互动画主观仍不流畅 | 同 GPU 路径未消除交互问题，需继续采样帧间隔 |

NVIDIA 与 Intel 的严格 A/B 对比仍待补充：同构建、同窗口尺寸、同缩放、同动画、
记录设备与驱动、采样时长、绘制耗时及提交间隔。不能把上述顺序试用当作受控对比。

## 3. HUD 口径（核对锁定版本源码）

- 默认 headline 带 `MAX`，由平均 `Window::draw` 耗时的倒数推导，并受显示器刷新率限制。
- 右键 HUD 切换实采 headline；`INTERVAL` 取相邻 `present_end` 的间隔，
  `FRAME` 为绘制耗时，`P95` 同样描述绘制耗时。
- `present_end` 在 `platform_window.draw` 返回后记录。Linux 上不能等同于
  合成器 `wp_presentation` 反馈或面板实际扫描完成；本报告称其为“提交间隔”。
- 该版本 HUD 默认预算是 60Hz 的 16.67ms；240Hz 检查需显式设 4.17ms，
  否则掉帧比例不能代表 240Hz 预算。
- HUD 有低频读数/资源采样刷新。静止窗口重绘与空闲资源检查必须关闭 HUD 复测。

## 4. 复现

```sh
cargo build --release -p mail-ui --locked
WAYLAND_DISPLAY=wayland-1 QINGMAIL_FPS=1 \
  VK_DRIVER_FILES=/usr/share/vulkan/icd.d/intel_icd.json ./target/release/mail-ui
```

右键 HUD，连续切换主题并点击列表/按钮；同时记录 headline 模式、INTERVAL、FRAME、
P95 和窗口尺寸。短涟漪与空闲时段混合的滚动 FPS 不能直接作为持续动画帧率。
默认运行不设置 `QINGMAIL_FPS`；`QINGMAIL_FPS=0` 也不显示 HUD。

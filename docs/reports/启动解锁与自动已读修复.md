# 启动解锁与自动已读修复

日期：2026-11-20，基于1.0.1后续源码。本轮不改数据库或IPC版本，不更新Arch包。

## 启动解锁

原来的密钥库接口检测到锁定后直接返回错误，启动自动同步不会触发系统解锁。本轮新增`SystemVault::request_unlock`：正式前台存在账号时，在后台线程检查现有凭据使用的默认集合；已解锁则直接通过，锁定则调用Secret Service的Unlock/Prompt，由系统负责密码对话框，不读取或接收解锁密码。完成后再次核实锁定状态，再请求一次合并收信，解除先前因锁定产生的同步等待。

每次前台启动只主动检查一次；新的启动器/托盘激活可重试先前取消的请求，账号页“检查系统密钥库”也可重试。用户取消后继续提供本地缓存阅读，不在轮询同步中反复弹窗。无账号、隔离探针或仅运行daemon时不自动请求解锁。等待对话框最多120秒；关闭/退出会取消等待，取消检查间隔25毫秒，不让解锁等待拖住退出。

## 打开邮件自动已读

正文仍使用BODY.PEEK读取；此前界面没有补充已读操作，因此打开后仍保持未读。本轮在所选邮件的正文成功交给阅读器后，通过原有持久离线队列提交单封`seen=true`，不改星标，不使用批量勾选目标，不等待服务器联网响应。落盘确认后更新当前文件夹、统一收件箱和搜索结果内同一完整身份的显示；后台按原流程同步服务器。加载失败、取消或迟到且已离开当前选择的结果不触发已读。

请求直接送入原有异步存储队列以保证与后续显式操作的先后关系；同一封在等待确认时去重。确认响应丢失时查询原请求的持久结果，不自动产生新请求重放。失败保留正文并提示标记未确认，不假报已读成功。

手动“标为未读”优先于较早的自动标记回调；普通缓存刷新不会因阅读器仍然打开而再次标记。再次点击/用键盘打开该封邮件时恢复自动已读。所有匹配使用账号、文件夹、UIDVALIDITY、UID，防止同UID跨账号或文件夹串改。

- `cargo test -p mail-ui read_state::tests --locked`：2项通过。覆盖原请求结果恢复且不重放、错误邮件身份响应拒绝、跨账号/文件夹/UIDVALIDITY投影隔离及星标保留。
- `cargo test -p mail-storage operations::tests::overlay_survives_server_refresh_restart_and_atomic_lost_response --locked`：1项通过，复验现有离线标记投影跨同步、重启及响应丢失保留。
- `python3 -B tools/read_state_probe.py`：隔离原生窗口通过，覆盖正文显示后标记、批量勾选不受影响、手动未读跨刷新保留、重新打开、缺失正文加载失败、快速切换取消及搜索与列表一致。证据在`dist/verification/auto-read.json`及同名日志；复用发送确认探针的隔离执行器。

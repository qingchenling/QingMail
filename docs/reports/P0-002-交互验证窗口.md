## 3. 过程中发现并修复的问题（上游 API 语义）

1. **`Window::request_animation_frame` 只能在绘制阶段调用**。其内部访问 `current_view()`（带 paint/prepaint 断言），从事件回调调用直接 panic（首次闪退根因）。改用 `Window::on_next_frame`，它自行调度新帧。
2. **主题过渡重定向竞态**。`advance_component_theme` 要求调用方逐帧推进且"只保留一个待推进回调"；每条闭包链捕获各自的 target，连续点击产生多条链互相覆盖，表现为"点击不管用"。修复：目标存于视图状态，单一 pump 循环每帧读取最新目标完成重定向。
3. **同实体重入 update panic**。`entity.update` 不可在监听器已持有的同实体 update 上下文中再次调用（`cannot update mail_ui::Home while it is already being updated`）。修复：首次推进在 listener 上下文内联执行，仅 `on_next_frame` 回调（无活跃 update）内使用 `entity.update`。

> 记录原因：这三条属于 gpui-kit/gpui-pre 0.3.12 的关键行为约束，后续所有窗口代码（含编辑器、阅读页）都会复用主题推进与弹层模式，必须遵守。

# P2 阶段总结（2026-11-16）

> 本文是 P2 的收尾总结；最新待办与真实账号验收状态以 [P2 当前状态与剩余工作](../P2-当前状态与剩余工作.md) 为准。

## 1. 结论

P2 的**实现范围**已收尾：单账号添加与管理、手动/低频自动收信、本地缓存与历史加载、简化阅读、回复/转发、草稿、发送与已发送副本、发送任务、基本邮件操作、本地搜索与正式界面整合均落地。

P2 的**阶段退出条件尚未满足**：真实 Secret Service + 通用账号的持续使用、原生交互与“无重复发送”证据必须由操作者用测试包执行；代理没有使用真实凭据、没有向真实收件人发信。

当前状态：**实现收尾，验收进行中**。测试包与验收清单见 [P2-020](P2-020-F验收准备与测试版.md)。

## 3. 关键实现与复用

- 依赖方向：`mail-core ← mail-content / mail-storage ← mail-service ← mail-daemon ← mail-ui`；协议层不依赖 SQLite，UI 不直接开数据库。
- 发送状态机是唯一写入口：`SmtpAttempt` 许可、`CopyPending` 隔离、失败/不确定禁止自动重发（ADR-0005）。
- 冻结快照确定性重建 MIME；预览、SMTP、APPEND 使用同一字节。
- IMAP 认证/响应边界/特殊文件夹/期限复用同一骨架；发送任务、存储线程、阅读组件均复用既有组件，不新造第二套。
- 设置/搜索/状态文案等跨窗口能力集中在 storage、`send_labels`、`settings`；主界面内嵌 Reader，不复制正文渲染。

## 4. 验证与证据

自动证据：

- 129 个 Rust 测试通过（各轮报告存 `docs/reports/evidence/` 日志）。
- 协议分支使用本机 TLS 假服务器：TLS/STARTTLS、认证、命令序列、字面量、APPEND/APPENDUID、MOVE/退化、SEARCH BEFORE、超时。
- 协调测试注入 Fake Vault/模拟投递与副本结果：并发点击、丢弃接收端、重发、失败后门控、状态恢复。
- 存储测试：迁移、对象完整性、对账、标记、搜索、账号移除。
- 门禁：fmt、check、clippy `-D warnings`、release。

历史原生证据：P0 生命周期/阅读/编辑器、P1 主要流程、P2-005 邮箱、P2-010 发送预览等曾人工/探针通过，但**不能代替本轮 A–E 新增界面的验收**。

未验证：真实 Secret Service、真实 IMAP/SMTP 账号、真实投递与已发副本、Wayland 原生交互与视觉、真实网络故障与持续使用。

## 5. 已知缺口与取舍

| 项目 | 状态 |
| --- | --- |
| 附件按部分下载 | 未实现；仍整封 MIME（≤8MiB）。需要操作者确认取舍，或单独立项 |

| 回复线程头 | 未设置 `In-Reply-To`/`References`，收件端不串会话 |
| 富文本剪贴板 | GPUI 只暴露文本；提供显式“粘贴 HTML”，非系统富文本粘贴 |
| 主题 | 浅/深色，不跟随系统；设置损坏静默回退 |
| 移动/删除撤销 | 未提供；标记可撤销 |
| 位置记忆 | 选中 UID 与分页游标，不保存滚动像素/窗口尺寸 |
| 真实账号验收 | 未执行；测试包已准备 |

## 6. 退出条件评估

| 条件 | 状态 |
| --- | --- |
| 真实通用账号添加/收信/阅读/发送/已发副本 | 未验证 |
| 持续使用、重启可靠 | 自动恢复测试通过；真实持续使用未验证 |
| 无重复发送 | 状态机与模拟故障测试通过；真实 SMTP/APPEND 故障未验证 |
| 已知限制记录与取舍确认 | 已记录；附件取舍待确认 |
| 原生界面/键盘/IME/窄窗/缩放 | 部分历史证据；A–E 新增交互未验收 |

因此 P2 **不能标记为已通过**；完成测试包验收并修复发现的问题后，才能写“通过”的结论。

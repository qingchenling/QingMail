## 1. 交付范围

`mail-content` 从 stub 变为可运行的内容管线，保留原始邮件字节，生成彼此独立的
受控简化文档与单文件浏览器副本。后台核心不依赖 UI，未引入 WebView、Electron、
真实邮箱连接或 OAuth。

原生窗口提供“阅读验证”入口；也可运行：

```sh
cargo build --release -p mail-ui --locked
WAYLAND_DISPLAY=wayland-1 VK_DRIVER_FILES=/usr/share/vulkan/icd.d/intel_icd.json \
  ./target/release/mail-ui --content-demo
```

该参数额外打开合成邮件阅读窗口。支持样本切换、选区/复制、简化/纯文本切换、字号调整、
“在浏览器中打开”、图片阻止状态与仅为当前邮件授权加载、附件另存为、立即清理副本。
解析、图像解码、网络加载和文件写入放到后台，忙碌时禁止切换邮件以避免结果串用。
关闭窗口后异步结果不再更新已释放视图。

阅读窗口继续遵循系统省电策略；本轮不修改报告 004 的产品选择。

### MIME 与资源

- 邮件输入最多 8 MiB；MIME 深度 32、部件数 256、编码嵌套 4。
- 正文最多 512 KiB；HTML 最多 20000 节点、64 层。超过限制时显示受限纯文本及提示，
  不呈现空白阅读页。原始邮件保留；无法识别结构时显示转义后的受限原始文本。
- HTML 原生展示只接受受控节点导出的 HTML；不把原邮件直接交给 TextView。
  原生文本中没有 img URL，图片以已校验的内存 PNG 在正文后集中显示，
  因而原生 HTML 组件没有自行请求远程图片的路径。
- CID 只查当前根消息部件；不跨邮件或借用嵌套 message/rfc822 资源。重复 CID 整组阻止。
- 最多 32 张图片；每张输入/输出最多 2 MiB，宽高最多 4096，总像素最多 400 万，
  解码分配上限 32 MiB，图片输出合计最多 8 MiB。校验实际格式与 MIME 声明，
  解码后重编码 PNG；SVG、未知/伪装格式与损坏图片不作为内嵌图片放行。
- 附件名仅展示，绝不拼成路径。另存为使用用户文件选择器，建议固定安全名称，
  create_new + 0600 保存，不覆盖已有文件，不自动执行或打开附件。

### HTML 与 CSS

明确允许段落、标题、强调、列表、引用、链接、图片与基础表格；移除脚本、事件、
iframe/object/embed、SVG/MathML、主动媒体、表单能力、meta refresh、base、外链样式等。
普通链接仅绝对 http/https/mailto，不保留相对、file、脚本与带凭据 URL。

CSS 使用声明属性允许列表与令牌解析；允许基础字体、颜色、边距、边框与表格布局。
URL、CSS 变量、未知函数、@import、@font-face、动画等不保留；颜色函数仅 rgb/rgba/hsl/hsla。
样式选择器限定基础元素/类/后代/子元素并作用域化到邮件正文，不能改变应用生成的副本说明。
不保留 @media 等未支持规则，不能保证营销邮件完全保真。HTML/CSS 安全清理不使用正则。

浏览器输出单文件 HTML，允许的图片仅为应用生成的 PNG data URI；附 CSP、referrer 禁止、
默认网络/脚本/对象/表单阻止。资源省略有明确提示；保持可支持的发件人配色，不强制反色。

### 明确授权后的远程图片

解析和默认阅读不进行网络操作。用户按“仅为此邮件加载远程图片”后，只遍历本封 HTML
img 的 http(s) 地址，不授权 CSS URL、字体、脚本、表单或主动媒体。
客户端不继承邮箱凭据/cookie，不发送 Referer、不用系统代理；正常验证 TLS。
每跳校验协议、凭据、DNS 地址并固定解析结果；最多 3 次跳转，禁止 HTTPS 降级 HTTP，
拒绝回环、私有网络、链路本地、多播和保留地址。连接超时 3 秒、单跳请求超时 8 秒，
限制响应大小与 Content-Type，下载后仍走图片解码/重编码校验。

本轮验证了本地/私有地址拒绝，未联网验证公共图片服务商及其 CDN 重定向成功路径，
也未实现 DNS 解析取消；这是该入口的已知限制，不能宣称完整远程加载兼容性已通过。

### 副本文件与清理

原生演示副本保存到 `$XDG_CACHE_HOME/qingmail-p0/reading-copies`，
未设置时使用 `$HOME/.cache/qingmail-p0/reading-copies`。
该目录必须属于当前用户且为 0700；文件用 128 位随机名称、EXCL/NOFOLLOW、0600 创建。
使用目录 fd 锚定创建和删除，不跟随副本目录/文件符号链接。

每次打开副本库清理超过 24 小时的受管理普通文件；立即清理只删除应用命名的文件，
不递归、不处理任意用户路径、链接或无关文件。界面说明立即清理可能影响仍打开的副本。
写入失败尝试删除未完成文件；异常中断留下的过期副本在下次打开副本库时清理。

## 3. 自动测试与真实浏览器证据

10 份可确定性生成的合成 `.eml`，覆盖清单见
[样本说明](../../tests/fixtures/mime/README.md)。

Rust 测试覆盖：字符集/头部/alternative、CID 唯一性与跨消息隔离、危险附件名、
SVG/超大图拒绝、脚本/URL/资源清理、可读降级、私有网络拒绝、目录/文件权限、
随机命名、24 小时/立即/异常残留清理与符号链接防护。

真实 Firefox 160.0（本机隔离 profile、headless、file:// 阅读副本），
使用 WebDriver BiDi 与本地 HTTP 探针实际加载页面，结果：

| 项 | 结果 |
| --- | --- |
| 清理后副本，带 CSP | 无脚本标记、0 探针请求，中文可读 |
| 清理后副本，移除 CSP | 同上，证明清理本身有效，不只依赖 CSP |
| 未清理正对照 | 脚本执行标记 9，收到 /script、/pixel、/redirect、/redirect-target |
| 清理副本中故意重新插入脚本/远程图 | CSP 独立阻止，0 探针请求 |
| 普通绝对 HTTP 链接 | 载入前无请求；显式激活后收到 /clicked |
| 合成营销邮件 | 中文、2 个嵌套表格、背景色、32×20 CID PNG 实际解码通过 |

除上述资源/浏览器兼容限制外：

- 简化文档的内嵌图集中在正文后，原位只展示标识；浏览器副本保持图片原位置。
- 简化表格不保证嵌套/合并单元格的原始布局；完整支持的排版以浏览器副本为准。
- 默认浏览器启动 API 无完成回执，界面只能报告“交给系统”并提示检查默认浏览器配置；
  已处理副本生成/地址转换错误，未宣称能检测浏览器进程内部的打开失败。
- 原生文件选择器/附件保存、公共远程图成功路径、其他浏览器及额外缩放矩阵需分别验收。
- 本轮没有实现正式产品阅读页、大规模列表或完整资源缓存服务；仍为 P0 合成原型。

完成本轮验收后，下一迭代按 ADR-0006 验证原生富文本编辑：中文 IME、撤销/重做、
选区、格式切换与受控草稿序列化，产出差距报告；不静默改成纯文本写信。

# 草稿生命周期、删除与冲突界面修复

2026-11-19。当前源码 schema22 / IPC v4；配套调试前后台已构建，未重新打包或安装。

## 原因与统一规则

此前把“本地是否保留”“上传结果是否确定”“两端是否同时修改”混在同步状态中：停止上传的草稿仍可能有未决 APPEND，后台排除停止状态，删除又要求先解决上传；扫描还可能把本机尚未核验的上传当作新草稿导入。冲突选择会额外创建编辑副本，界面同时展开目录、原件、诊断和所有决策，难以辨认要处理哪份草稿。

行为规格集中维护于 [草稿生命周期与冲突处理](../design/草稿生命周期与冲突处理.md)。本轮实现：

- 本地保存与云端同步分开。上传结果未知时只核验冻结的原上传，不重新 APPEND；当前正文已清空或编辑版本已变化，也不能丢弃旧上传证据。
- 用户删除在同一事务中移出列表、取消尚未开始的上传、关闭冲突并清除编辑选择。未决上传或暂不能清理的云端副本保留为内部删除记录；迟到的保存、选择和发送不能复活它。
- 删除不等待联网或先处理冲突。后台只核验、清理具体账号/文件夹/UIDVALIDITY/UID；缺少垃圾箱、定位变化或队列满时保留状态，不声称云端已删除。冲突中已明确关联的远端原件也纳入这次删除。
- “仅保留本地”不增加版本、不新建编辑副本，停止这份草稿的云端同步；重启、再次编辑和迟到错误均不能重新打开已处理冲突。删除该本地草稿后，仅恢复旧上传的核验及清理。
- 扫描本机未决上传时，复用上传核验的内容比较规则，避免重复导入。关联标识相同但内容不同，保留为真正的远端冲突；不能只凭邮件头猜测删除。允许的 QQ 传输追踪头与正文、原始邮件头修改严格区分。
- 核验本机上传不能解除另一份云端修改造成的冲突，也不能提前清理其共同基线和原件。发送快照与 SMTP 禁止自动重发的约束保留。

## 冲突界面

- 默认打开当前选中的草稿；一次展示一份问题，其他草稿通过主题切换。
- 本地与云端分成两张版本卡，使用简短原因说明。“上传结果待确认”提供继续核验、仅保留本地；真正版本冲突提供保留两份、使用本地、使用云端。
- 删除使用共用垃圾桶图标，版本选择与删除提供就地确认及取消。
- 目录设置、手动扫描、历史原件和技术原因默认折叠；打开页面只读状态，不隐式修改目录或扫描服务器。
- 进入前先保存当前编辑；返回时重新读取草稿，避免继续编辑已删除或已替换的旧版本。底栏显示尚未结束的云端清理。

“使用本地”不额外创建编辑副本；只有替代上传核验成功，才把明确关联的旧云端版本排队移入垃圾箱，本地原件仍可恢复。“保留两份”仍是明确保留两个编辑分支。

## 数据与验证

schema21→22 顺序迁移并在升级前备份；新增草稿删除标记与单份草稿的仅本地策略。原有账号、正文、附件、原件及冻结发送记录不通过删除数据库重建来修复；旧程序拒绝新版本数据库。

仅执行相关检查，没有运行工作区全量测试：

- 存储：草稿上传/扫描/刷新/冲突、删除事务回滚、重启及迟到结果、账号隔离、发送快照与状态机，以及受此次迁移影响的旧版本升级夹具。
- IPC：删除响应重放、草稿保存响应丢失、未决上传跨后台重启后删除、冲突选择重放；合成数据下确认没有 SMTP 任务。
- 服务：8 项本机模拟服务器测试通过，包括未知结果只查询、只读扫描、有限查证回退、QQ 传输头和原件内容验证。
- 界面：草稿标签与底栏同步状态定向单元测试；原生隔离草稿探针通过空态、新建、多草稿切换前保存、关闭重开、未保存修改时删除、最后一份删除、回到收件箱、单窗口及底栏自动刷新。证据为 `dist/verification/draft-lifecycle-ui.json` 及同名日志。
- fmt、受影响 crate 的 check / clippy（all-targets，-D warnings）通过；配套 UI、daemon 调试构建完成。

没有修改真实数据库、读取凭据、发送真实邮件或删除真实服务器邮件。冲突页的视觉体验、真实服务器遗留上传恢复仍需用户复验，隔离测试不替代真实兼容验收。测试前先在应用中选择“保存并退出”，再运行新的 `target/debug/mail-ui`；仅关闭窗口不会退出旧后台，`cargo run -p mail-ui` 也不会构建后台。

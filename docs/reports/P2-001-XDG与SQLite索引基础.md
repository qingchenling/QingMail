# P2-001 · XDG 与 SQLite 索引基础

- 日期：2026-11-16
- 状态：本轮存储基础完成；P2 单账号闭环仍在开发。
- 依据：主文档 §3.1、§4.1～4.3、§9；ADR-0001～0006；P1 已确认交互规格。

## 1. 本轮实现

`mail-core` 补入非秘密账号连接配置（IMAP/SMTP 各自的主机、端口、用户名和 TLS/STARTTLS）、文件夹、邮件索引和本地稳定 ID。没有密码、令牌字段，也没有明文连接或跳过证书检查选项。配置字段仅做基础边界检查，完整邮箱格式及连通性验证仍由后续账号流程负责。

`mail-storage` 从 stub 改为 SQLite 索引库：

- 解析 XDG config/data/cache/runtime，未设置的前三项按 HOME 回退，忽略相对 XDG 值；runtime 不回退共享 /tmp。仅实际打开的 data 目录会创建，默认 `$XDG_DATA_HOME/qingmail` 或 `$HOME/.local/share/qingmail`。
- 数据目录 0700，数据库、写锁、迁移备份 0600；拒绝目录路径软链接、特殊文件、不符权限及数据库/锁的硬链接。不修改已有宽权限目录，而是返回错误让调用方明确处理。
- 目录 fd 持有与 Linux `/proc/self/fd` 定位；单写者文件锁覆盖连接整个生命周期；数据库 sidecar 在打开前检查，连接不向 UI 暴露。
- schema v1：accounts、folders、messages、folder_messages。账号/文件夹/邮件本地 ID 随机生成并持久化；文件夹路径不冒充本地稳定 ID，Message-ID 不作为全局去重键。
- 账号枚举/读取、账号创建、文件夹读取/更新、邮件索引幂等写入及 UID 倒序游标分页（每页最多 200）。分页尚不等同最终产品日期排序和完整历史搜索。
- 文件夹关联定位为账号 + 本地文件夹 ID + UIDVALIDITY + UID；外键约束禁止跨账号关联，并为一封邮件关联多个文件夹保留结构。
- UIDVALIDITY 变化在同一事务删除对应文件夹关联、更新 epoch；旧定位写入失败并回滚，其他文件夹不受影响。旧邮件对象暂保留，不自动清理可能被后续草稿/任务引用的内容。

本轮没有将 Store 接入 UI 或后台工作线程，没有在用户正式数据目录写入合成账号；测试全部使用隔离临时目录。现有 P0 窗口和 target 单槽草稿路径保持原行为，正式草稿迁移尚未完成。

## 2. 依赖与数据库策略

选择并精确锁定 `rusqlite =0.43.0`（MIT，MSRV 1.89，兼容本项目 Rust 下限），关闭默认 feature，仅开 bundled、backup。新增锁定 `libsqlite3-sys 0.40.0`，内含 SQLite 3.54.1；由 bundled 提供确定的 SQLite 版本，不依赖用户系统 SQLite 的构建选项。完整 Cargo.lock 已更新；GPUI Kit、Material、FPS 和 GPUI snapshot 均未升级。

使用同步库，由后台单写者持有；不引入异步连接池和第二个数据库写入者。当前选择 DELETE journal + synchronous EXTRA + 外键开启 + trusted_schema 关闭，避免在首轮引入 WAL checkpoint 生命周期。打开时执行 quick_check 和 foreign_key_check。

通过 application_id 与 user_version 验证归属及版本：新空库事务初始化为 v1；已有空 v0 在迁移前用 SQLite backup API 保存随机命名备份并同步。迁移 SQL 和版本更新属于同一事务，失败不留下半张表。未知未版本化结构、其他应用数据库、损坏文件和较新版本均报错保留，不删库重建。

当前仅实现 v0→v1 初始化，没有假称已经验证未来版本升级。备份不自动恢复或自动删除；将来升级需新增版本迁移、恢复说明及对应数据样本测试。异常备份须先验证完整性，不能把文件存在视为备份成功。

## 3. 验证证据

存储 9 项测试：

1. XDG 绝对覆盖、相对值回退、运行目录无不安全回退。
2. 重开后的账号/文件夹/邮件 ID、中文/emoji、账号隔离、重复同步、最大 u32 UID 和游标分页。
3. UIDVALIDITY 变化只失效目标文件夹，旧定位写入失败且不留下孤立新记录。
4. 同账号多文件夹关联允许，跨账号关联与零 UID/epoch 拒绝。
5. 0700/0600、重复写者、目录/数据库/sidecar 软链接与硬链接拒绝。
6. 较新版本、其他应用和损坏数据库拒绝打开，原文件字节保持。
7. 故障注入迁移中途 SQL 错误：事务回滚，保留 0600 可读备份，随后正确初始化成功。
8. 子进程在事务中直接退出、不执行析构：重新打开保留此前提交账号，不含未提交改动，写锁可重新获得。
9. 数据目录不可写导致保存失败：恢复权限后重新打开，仍只有最后成功提交的账号。

最终门禁：fmt --check、workspace check --locked、workspace test --locked、clippy --all-targets -D warnings、release mail-ui build 通过。全项目 29 个 Rust 测试通过；保留既有 5 条 stub manifest 未用依赖提示，无新增 Rust/clippy 警告。无 UI 改动，本轮不要求操作者重复窗口验收。

这些测试不代表机器掉电、磁盘硬件损坏或网络文件系统上的完整耐久性认证；后续故障测试仍需覆盖正式草稿和发送状态机。

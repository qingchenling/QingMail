## 1. 范围与入口

主窗口新增“邮件”入口，账号窗口已保存账号下增加“打开邮件”。支持 `--mailbox` 单实例重开/激活，同一进程复用邮件窗口。原生窗口展示账号→服务器文件夹层级，支持真实 NoSelect 目录与由路径生成的中间父节点，展开/折叠与选中文件夹分开；折叠不清空选择。靠左容器和树行均为直角。分隔符来自 LIST，不假设所有服务器都用 `/`；modified UTF-7 中文显示与服务端原始标识分离。

启动只读取本地账号、已确认的文件夹目录与索引，不自动联网。首次保存账号后可从邮件窗口“重载本地账号”，再“刷新文件夹”；选择文件夹先显示缓存，点击“同步最近邮件”才加载邮件头。UI 明确本轮只读、最近90天、每页最多200封；缓存不代表服务器实时镜像。无账号、尚未同步、本页无缓存分别反馈。后续完整欢迎页、响应式抽屉和产品主窗口替换仍待实现。

邮件索引使用 uniform_list 仅绘制可见行，UID 倒序取200条，不把 UID 当日期排序。单击选择后显示主题、发件人和日期；列表获得焦点后上下键可移动选择。≥1050逻辑像素采用列表/详情双栏，较窄时详情在列表下方，左树宽208；极窄窗抽屉、分隔线拖拽、每个文件夹滚动位置记忆及完整键盘树导航尚未实现。详情明确正文尚未下载，不呈现未经获取的正文，不改变远端已读状态。

缓存支持“下一页缓存 / 返回最新缓存”；“查询较早邮件（90天内）”以本页最后UID继续在最近90天查询结果内分页，不冒称加载90天以前历史。同步失败保留上次确认的目录与缓存，用户可明确重试；不将时间范围外或未返回的邮件推断为服务端已删除。

## 2. 只读协议与执行边界

复用 P2-004 的系统密钥库读取、TLS/主机名校验与认证连接。LIST 获取服务器目录；单文件夹使用 EXAMINE、UID SEARCH SINCE、UID FETCH `(UID BODY.PEEK[HEADER.FIELDS (SUBJECT FROM DATE)])`，最后尽力 LOGOUT。无 SELECT 写会话、STORE、MOVE、COPY、EXPUNGE、APPEND 或 SMTP 提交。原生窗口仅由明确点击触发网络任务。

响应使用 imap-proto 0.17.0，头部使用已有 mail-parser 1.0.1 解码 RFC2047 中文主题/发件人/日期；缺日期显示未知，未把邮件 Date 伪称服务器 INTERNALDATE。保留账号/文件夹/UIDVALIDITY/UID 定位，不按序列号或 Message-ID 合并。UIDVALIDITY 必须存在且非零；较早分页若发现 epoch 变化即停止，提示先同步最新邮件，不把旧分页游标套用到新 epoch。FETCH 缺项/重复或响应失败不返回部分批次；服务器查询期间删除邮件导致缺项时本轮保留旧缓存并提示重试。

网络任务在 GPUI 后台执行，SQLite 仍只在 storage 工作线程使用；不把网络等待放入存储线程，以免阻塞草稿保存。窗口同步互斥，只允许一项网络检查，关闭后新窗口遇到尚未结束的旧检查会提示稍后重试。关闭窗口丢弃尚未发布的响应；已交给存储线程的完整批次仍按队列提交。没有网络立即取消令牌、IDLE、定时轮询、退避重连或自动通知，本轮仅手动同步基础。

每条连接 TLS 后累计响应1MiB/20秒软截止，socket单次读写5秒；同步每命令至多4096条响应、SEARCH至多10000个UID，每页至多200封、单个头部字面量64KiB。解析前校验括号深度≤16，跳过字符串/字面量数据，避免通用 FETCH 解析器处理过深嵌套。完整 FETCH 成功但超过预算仍报错并保留旧缓存。系统 DNS 尚无独立取消期限，因此不承诺严格总时限。大邮箱超过当前上限会明确失败，后续需分段 SEARCH/头部拉取和长期连接管理。

## 3. SQLite v4 与发布规则

schema v4 增加 remote_folders、catalog_sync、folder_sync。LIST 目录与已 EXAMINE 的 folders 分离，NoSelect 节点不虚构 UIDVALIDITY。LIST 完整成功后事务替换该账号目录，记录确认时间；目录移除不删除旧邮件对象。单文件夹整批发布在同一事务完成：UIDVALIDITY变化时清空仅该文件夹的旧UID关联、更新epoch、写入新头部和同步元数据。SQL失败回滚，不能出现新epoch搭配半份旧缓存。

同一四元定位重复同步更新已有消息，保持本地MessageId；其他文件夹/账号不受epoch变化影响。最近90天查询无返回不删除范围外邮件；远端删除/移动与本地失效标记、历史回填和孤立对象回收尚未实现，因此UI持续提醒缓存可能含远端已移除的邮件。

已有v1/v2/v3库升级先私有备份，事务升级至v4；v3本地草稿结构只在version<3时应用，避免v3→v4重复执行。更新v2迁移测试夹具以移除v3/v4结构，原草稿正文保持。原生编辑探针改核对schema4，之前验收资料保留原版本不重写。

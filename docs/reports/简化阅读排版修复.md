# 简化阅读排版修复

日期：2026-11-19。基于1.0.1后续源码，未重新打包。

## 原因与改动

用户截图中“创刊于 / 1965 / 年”等短句被拆成多段。受控文档转换把span等行内标签归类为Container，导出为div，导致原生排版额外换段。本轮将装饰性行内包装展开，保留粗体、斜体和安全链接；只去除没有实际内容的撑高段落，不猜测合并真正段落，不删改正文。pre、显式换行、表格及列表结构保留。

原来的阅读器将正文图片替换成占位符，再把全部图片集中追加到底部；且分别截取宽高，可能改变比例。本轮增加native_html_with_images，只输出对应已验证PNG的qingmail-image索引。复用已有TextView.image_source提供权威内存资源映射，不允许回退到远程地址、本地路径或任意data内容。图片按正文位置展示，宽度最多640逻辑像素，窄栏缩小并保持比例，不放大小图；去掉底部重复图片集中区。

正文最大宽度760逻辑像素，行距1.7，段距0.65rem；继续复用M3E颜色、现有字体大小、可选择复制、纯文本切换及浏览器阅读入口。浏览器副本继续使用独立的原始安全HTML/CSS，不因本轮原生排版修改放宽资源规则。原始MIME、附件下载、自动图片开关均不变，无数据库或IPC版本变更。

## 验证及限制

- 受控文档3项：中文newsletter中span与粗体不拆句；空段清理及pre/换行保留；图片顺序与越界资源索引。
- content_pipeline定向集成5项：中文编码、CID、表格、损坏降级和恶意资源处理。
- 阅读器定向2项：自动加载策略及私有图片索引解析器拒绝任意网络/文件资源。
- 隔离原生阅读窗口冒烟测试通过：缓存正文、CID图片、纯文本/HTML切换及浏览器副本生成。证据位于dist/verification/reading-layout.json及同名.log，仅使用合成邮件，不访问真实账号。
- fmt/check/clippy与配套UI、daemon调试构建通过；没有运行全量测试或真实邮件发送。

原生冒烟不等于截图中真实newsletter的视觉验收。需要选择“保存并退出”后启动新版target/debug/mail-ui，再打开原邮件复验；正文仍经过安全简化，不承诺复刻原邮件全部CSS。未提交Git或更新Arch包。


## 2026-11-20：排版表格与图片失败原因

针对新截图，仅以只读方式定位对应缓存HTML，未登录邮箱、修改数据库或发信。该HTML用14层/处`role="presentation"`表格布局，没有数据表头；此前原生阅读把它们当作数据网格，形成边框和集中挤排。本轮清理器保留受限的table role（presentation/none），原生转换展开布局表格及其行/单元格，同时保留嵌套真实数据表格。浏览器副本仍保留原始清理后的布局。空alt图片占位改为“[图片未加载]”，去掉空冒号。

图片失败已证实为本机DNS返回`198.18.0.77`（代理Fake-IP），被原有私网/保留地址限制拦截。对邮件引用的两个图片地址进行只读HTTP检查，均返回200和PNG：149×35、1672×941，分别约6.4KB和1.68MB；下载结果也通过实际`validate_image`校验，派生PNG约6.5KB和1.66MB。不是图片损坏或超限。

初次诊断时建议手动设置代理Fake-IP排除；此建议已被下文“独立图片DNS解析”实现替代，现在无需手动修改代理。198.18/15仍不直接放行。

图片失败改为可区分的提示：Fake-IP无法取得真实地址、私网阻止、DNS失败/超时、HTTP状态、响应类型、体积、连接及响应失败。只显示必要域名，不泄漏带令牌的完整URL。重试替换旧图片失败提示，成功后清除旧提示；保留其他解析警告、失败URL和手动重试入口。

验证：document 4项、remote 5项、content_pipeline 5项，共14项相关测试通过，未运行全量测试。新增用例覆盖布局表格展开与嵌套真实表格、空alt占位、Fake-IP诊断但不放行私网/混合DNS，以及重复重试不累积警告。实际缓存HTML的离线解析从14个布局表格变为0个原生表格，两张图片本地校验均通过。fmt、相关Clippy及配套UI/daemon调试构建通过；未重新打包、未声称代理调整后的原生窗口实测通过。临时诊断副本只存/tmp，不提交真实邮件/图片/完整URL。

## 2026-11-20：独立图片DNS解析

用户选择由应用处理Fake-IP。新增`mail-content/src/remote/dns.rs`，复用现有reqwest、Tokio与serde，无新增依赖版本、数据库或IPC变更。

- 通常仍用系统DNS；只有域名解析包含198.18/15，且其余地址均为公网时才启用加密DNS。字面量Fake-IP、私网及混合私网结果仍拒绝。
- 优先AliDNS（`dns.alidns.com/resolve`），请求失败后尝试Cloudflare（`cloudflare-dns.com/dns-query`）。固定各自引导公网IP并校验HTTPS证书，不依赖系统对解析服务域名的解析，不修改代理配置。DNS服务仅收到图片域名与A/AAAA查询类型，不收到完整图片URL、邮箱凭据或邮件内容。
- 查询与图片下载均禁用代理继承；限制DNS响应32KiB/64条记录，验证问题匹配、CNAME归属/循环、地址族和公网地址；图片连接固定验证后的地址，保留URL主机名及TLS校验。每次重定向继续经过相同验证，禁止HTTPS降级。
- 真实地址仅在本次图片加载内复用，按DNS TTL且最多60秒缓存，端口取当前URL。DNS回退总超时8秒；请求可随退出取消，不等待完整超时。保留图片2MiB等原有限制及自动加载设置。
- 解析失败保留可重试提示，不把Fake-IP或其他私有地址当作可访问目的地。

验证：11项remote定向测试通过，覆盖回退触发条件、两种服务响应格式、CNAME/TTL/IPv6、恶意或损坏响应、缓存端口/过期，以及图片响应和加密DNS连接的退出取消。fmt与mail-content全目标Clippy通过，配套`mail-ui`和`mail-daemon`调试版构建通过。未运行全工作区测试。

使用缓存HTML执行实际Rust图片加载入口，系统此时仍解析为198.18.0.77，两张图片均自动解析、下载并通过PNG校验，约2.02秒完成；尺寸149×35与1672×941，未加载图片数为0，无远程图片失败警告。未登录邮箱、发信、修改用户数据库或代理设置；临时验证材料仅在/tmp。此结果是实际内容加载链路验证，不替代原生阅读界面的视觉验收。未更新Arch包；测试前应先“保存并退出”旧前后台，再运行新版`target/debug/mail-ui`。

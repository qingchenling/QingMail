# P0-007：进程内后台、单实例与关闭/重开

- 日期：2026-11-16
- 阶段：P0 迭代 5；依据主文档 §3、§6.2、§9、§11 与 ADR-0003。
- 状态：自动门禁、真实进程探针与原生桌面人工验收通过。
- 范围：无真实账号、无收发；一个进程中的后台线程与 GPUI 窗口。没有拆分 daemon，没有冻结 P3 IPC。

## 1. 运行行为

主窗口明确显示“关窗后后台继续运行，再次启动可重开”，显示 PID、合成工作计数和托盘可用性。GPUI 采用显式退出策略；关闭所有窗口仍保留应用进程，合成工作线程每 250 ms 推进计数。UI 窗口不持有后台寿命，窗口可销毁重建。

- 再次启动默认打开/激活原主窗口；`--editor-demo` / `--content-demo` 分别打开或激活唯一的编辑/阅读验证窗口。
- 主窗口及托盘均提供“保存并退出”；`--quit` 是无窗口时的恢复入口，`--status` 显示当前进程、计数与窗口状态。
- StatusNotifierItem 提供图标激活、DBusMenu“打开 QingMail／保存并退出”。无 D-Bus、无 watcher 或无 host 时，明确说明托盘不可用及再次启动/命令行退出路径，不声称注册成功。
- 本机 watcher 的 `IsStatusNotifierHostRegistered=true`；六项托盘协议检查在隔离 D-Bus 会话中运行，不替换用户桌面服务。
- 启动未成功建立后台时报告具体错误并退出，不自动循环重启。没有增加桌面自启动、系统服务或安装包。

## 2. 单实例与安全边界

`mail-daemon` 仍是被 UI 调用的库。私有激活通道位于 `$XDG_RUNTIME_DIR/qingmail-p0`；目录必须属于当前 UID、权限 0700，持有 `flock` 独占的 0600 锁文件，socket 0600。没有 XDG 运行目录或目录类型/权限错误时，明确失败，不回落到共享 `/tmp`。

P0 通道只接受 `QMP0 OPEN/EDITOR/READER/QUIT/STATUS`，无任意路径、URL 或执行入口；这是临时进程激活机制，不是 P3 的冻结 JSON IPC。连接双方检查 Linux peer UID；每个请求最多 32 bytes、读取/写入 200 ms，控制队列容量 32；调用端响应最多 512 bytes，读写超时 500 ms。确认回执仅表示请求入队；窗口和保存最终结果通过 UI/状态观察，不把请求已收当作退出已完成。

只有获得独占锁后才能删除本用户的残留 socket；拒绝替换常规文件或链接，正常退出清理 socket，保留锁文件。争锁期间在有限重试中同时尝试激活现有进程与重新取得锁，覆盖旧进程恰好死亡的竞争；不会仅凭连接失败删除活实例的端点。

合成工作线程、激活监听线程分别持有明确的停止标志；有界等待结束、join 后释放锁。实例锁线程不依赖窗口。系统强制结束/SIGKILL 不承诺保存未确认输入；重启时回收残留端点并恢复最后确认草稿。

## 3. 草稿关闭与退出

本轮延续 P0-006 的受控模型、版本回执与后台原子保存：

1. 关闭编辑窗口时，如果中文候选词仍在组合输入，提示先完成或取消，阻止关闭。
2. 恢复尚未完成则等待；保存开始后暂时只读，等待已有写入完成并刷新到最新 revision。
3. 最新版本确认保存后才销毁窗口；不把已经落后于当前编辑的保存回执当作完成。
4. 目录不可写等保存错误时取消关闭/明确退出，保留窗口及旧确认版本，提示原因；恢复写权限后可重试。
5. 明确退出时遍历存活的编辑窗口，全部保存关闭后才结束进程。普通关闭主窗口不影响仍打开的编辑窗口或后台。

草稿仍是工作区 `target/p0-editor` 的合成单槽，不是正式邮件存储。损坏文件/存储初始化失败时不覆盖原文件；需要排除文件问题并保留当前文本，本轮没有正式产品的“另存为／放弃未保存”异常交互。桌面会话被强制结束、进程崩溃、系统断电仅保证此前确认保存版本；未实现系统注销的延迟关闭协议。

## 4. 自动测试与真实进程证据

门禁均 exit 0：

- `cargo fmt --all -- --check`
- `cargo check --workspace --locked`
- `cargo test --workspace --locked`：21 个测试（内容 12、daemon 4、UI 1、其余 4）
- `cargo clippy --workspace --all-targets --locked -- -D warnings`
- `cargo build --release -p mail-ui --locked`

单实例 Rust 测试要创建本机通信端点，在限制该操作的环境中须在正常本机环境运行，不跳过测试。现有 5 条 stub manifest 未用依赖提示保留，无新增 Rust/Clippy 警告。依赖只增加当前 lock 已存在的精确版本 `zbus=5.19.0` 与 rustix `net` 能力；GPUI/M3E 快照未升级。

[真实进程探针结果](evidence/P0-007-lifecycle.json)、[过程日志](evidence/P0-007-lifecycle.log)，复现：

```sh
python3 tools/lifecycle_probe.py
```

工具仅在独立的 0700 临时运行/草稿目录中启动 release 窗口和激活进程，不读取或修改正常测试草稿；结束时清理自己启动的进程。九项检查：

| 检查 | 结果 |
| --- | --- |
| 未到自动保存时限即关闭编辑窗口，保留最新文字与粗体；无窗口时计数继续增长 | 通过 |
| 运行目录/socket 权限 | 0700/0600 |
| 8 个并发二次启动 | 同一 PID、单个编辑窗口 |
| 二次启动重建主窗口并保留编辑窗口 | 通过 |
| 非法、超长、停滞激活请求 | 拒绝或超时后恢复服务 |
| 明确退出与端点清理 | exit 0，socket 消失，草稿一致 |
| SIGKILL 后立即重启 | 回收残留 socket，恢复确认草稿 |
| 真实目录写权限故障 | 取消关闭/退出，保留窗口及旧确认草稿 |
| 恢复写权限后重试 | 干净退出 |

原生探针还在同一更新中构造标记预编辑，确认关闭被拒绝，取消后文档恢复（日志 `P0_PROBE`）。这是实际 GPUI 协议调用，不替代真实中文候选窗人工验收。

[托盘协议结果](evidence/P0-007-tray-probe.txt)，复现：

```sh
dbus-run-session -- env QINGMAIL_TEST_PRIVATE_BUS=1 cargo run -p mail-daemon --example tray_probe --locked
```

六项：无 watcher、无 host 降级；有 host 注册后属性与图标；菜单布局；激活/打开入队；退出入队。使用私有会话 bus，避免替换桌面 watcher。它不代替 Waybar 实际菜单绘制/点击验收。

## 5. 人工验收与限制

操作者对关窗后托盘重开、输入后立即关闭编辑窗口再重开保留最新文字、“保存并退出”后窗口和托盘图标消失，回答：“全部正常，本轮验收通过”。这覆盖本轮正常生命周期交互；故障/崩溃项以独立探针为证据。

- 后台仅是合成计数，未验证真实 IMAP 同步、SMTP、通知或队列恢复，不据此宣称无重复发送已完成。
- 托盘宿主启动/消失/重启的动态监控与重新注册尚未实现；没有宿主时始终可再次启动唤回或 `--quit`，不依赖托盘唯一入口。
- 临时激活通道按当前 UID 保护，未实现 P3 稳定协议、请求 ID、跨版本协商、多账号或 daemon 拆分。
- 单实例语义适用于本轮及以后的同一运行目录；不能接管此前不含实例机制的旧原型二进制。
- 生命周期探针使用独立环境变量 `QINGMAIL_P0_RUNTIME_ROOT`、`QINGMAIL_P0_DRAFT_ROOT`；诊断参数不是正式产品配置。旧编辑/性能探针保持隔离，不抢普通实例。
- 尚未进行长时间后台空闲 CPU/内存、跨会话、多显示器和完整缩放矩阵验收；中文斜体等编辑缺口继续见 P0-006。

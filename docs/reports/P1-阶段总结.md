## 3. P2 交接（当前进度入口）

P2 已推进至 P2-010。原先按顺序规划的正式存储、账号检查、阅读、多草稿及 SMTP 确认基础均已有实现，不再作为初始待办。逐项剩余工作、实现证据与阶段边界见 [P2 当前状态与剩余工作](../P2-当前状态与剩余工作.md)。以下为 P1 交接时确认的工作范围与验收要求，保留作为来源，不表示这些步骤仍全部未开始。

### 原定开发顺序与验收要求

1. 正式数据基础：XDG 目录、账号/文件夹/邮件稳定标识、本地持久化及迁移、密钥库边界、多草稿与发送任务数据模型；先做故障恢复验证，不沿用 target 单槽作为正式存储。
2. 通用账号接入：分别选择并验证 IMAP/SMTP 库，检查 TLS/STARTTLS、证书与认证失败；原生账号页只在检查和用户确认后保存配置。P0–P2 保持单进程内部模块边界，不冻结临时激活协议。
3. 接收与阅读：原生账号文件夹树、分页虚拟列表、增量同步、稳定定位、安全阅读与附件保存；重启恢复状态。
4. 写信与草稿：补齐受限富文本差距、清理后的回复/转发、多草稿、附件可靠引用、自动保存与关闭失败流程。
5. 发送闭环：先可靠持久化再联网，六状态和故障注入；不确定禁止自动重发，成功后副本失败只补存；离线草稿不自动发出。
6. 持续使用验收：真实通用账号同步—阅读—草稿—附件—明确发送闭环、重启可靠、无重复发送；补原生明暗、焦点/快捷键、IME、缩放及资源预算实测。

按小步迭代、适用门禁、报告与一次提交推进。真实账号凭据由用户按需提供，外部发送按具体用户授权进行；本次设计确认没有扩大该授权。完成 P2 退出验收后才进入 P3 多账号、离线完善和 daemon/IPC 拆分；OAuth 最早 P4。

# P3-002b：临时凭据与异步连接检查

日期：2026-11-17。基线：d36d154。状态：基础实现完成；账号安全提交及前台迁移待后续实现，P3-002 尚未完成。

## 实际交付

- `mail-service::credentials::staging` 提供 Secret Service 临时项创建、读取、丢弃与过期清理 API。随机128位引用、独立 purpose、创建时间，15分钟有效期；加密项内再次绑定引用和时间。正式账号凭据不覆盖、不删除，临时项无明文文件回退。
- 读取拒绝错误 purpose/application/ref、正式账号属性、时间篡改/未来时间、过期项与损坏编码；重复项或锁定状态明确失败。清理只处理本应用已过期 staging，每次最多256项，保留锁定与未知项。尚未启用生产启动清理钩子。
- daemon CheckManager 使用独立单线程检查，最多2个排队任务、16条短期结果；复用现有 IMAP/SMTP 连接认证检查，不发送邮件。队列满立即 Busy，控制线程与存储线程不等待网络认证。
- IPC v1 增补 AccountCheckStatus 与 AccountCheckPending。检查立即返回任务，按同请求ID查询/复用结果，不重复认证；相同请求ID不同配置/目标/引用报冲突。更新检查会先确认目标账号存在。
- 检查通过才提供5分钟令牌，绑定原配置、目标账号及实际检查过的凭据；凭据仅保留在后台受限内存中，消费后不能再用。认证失败、临时项过期、目标不匹配或服务重启都不能凭旧令牌提交。过期内存记录定时清理，退出等待检查线程并释放秘密。
- Hello 在网络能力启用时才列 CheckAccount/AccountCheckStatus；当前命令行隔离入口继续禁用密钥库/邮件网络。CommitAccount 仍 Unsupported，未把检查结果冒充账号保存。

## 1. 明确发送流程

账号写信窗口新增“检查并发送…”与Ctrl+Enter（仅打开检查，不直接提交）。未关联账号的本地草稿不能发送。输入法组合、附件导入或未保存内容先完成/保存，再重新检查；未完成写盘不能提交。存储线程基于当前持久草稿读取完整正文和附件副本，执行P2-009发送前检查，返回绑定账号配置、草稿ID与版本的SendReview，不创建任务、不联网、不读密钥。

检查通过后冻结编辑，显示发件人、To/Cc/Bcc、主题、附件数量/总量及正文摘要。“返回编辑”只取消预览。普通主题需点“确认发送”，空主题需点“确认无主题仍发送”；不存在自动确认路径。确认时再次核对编辑版本；后台还会重新校验数据库版本、账号配置、附件摘要与历史记录，防止过期预览提交。

“确认发送”已连接生产SMTP适配：操作者对真实账号点击此按钮会实际投递。本轮自动检查仅用合成数据和模拟协调结果，没有实际向外部投递。后续真实验收必须另行明确测试内容与收件人。

## 2. 后台与持久化

SendCoordinator由生命周期管理器持有，独立发送线程处理密钥与网络，SQLite仍只由原存储线程访问。先从Secret Service读SMTP密码，缺少凭据时不创建任务；之后在同一存储请求内复验预览、冻结Pending快照、验证最终MIME并取得持久Sending许可。网络结果消费该许可写回：接受→CopyPending，明确未投递→Failed，不确定→Uncertain。

协调器全局只允许一个在途提交；存储层也拒绝同一草稿的第二次许可。此阶段对有任何发送记录的草稿一律禁止再提交，即使后来改了版本也不能绕过。重发/停止处理的专门入口尚未实现；要写一封独立新邮件可新建草稿。后台不扫描恢复任务、不自动联网重试，不因网络恢复而发送。

关闭编辑窗口只释放界面，发送线程继续并持久结果；丢弃接收端不阻塞完成。应用“保存并退出”先完成草稿关闭，再等待发送线程结果写盘后退出。线程异常或写盘失败时提示不要重复发送；原Sending在下次重开按既有规则恢复为Uncertain。此阶段沿用5秒socket操作超时，DNS和整次提交尚无独立总deadline，所以慢网络下明确退出可能需要等待；未实现强制取消。

编辑窗口加载、切换、提交后或点“刷新发送记录”显示当前草稿至多50条记录。Failed/Uncertain/CopyPending有持续文字提示，不用短暂通知代替。历史异步读取用代号丢弃迟到结果，不把上次草稿或旧请求当当前状态。

SMTP接受仍显示“邮件服务器已接受；已发送副本尚未保存，请勿重发”。本轮没有IMAP APPEND和重试副本入口，不能把CopyPending标成完整Sent。失败记录目前仅保存既有固定诊断类别，尚不提供完整故障详情面板。SQLite保持schema5，未新增依赖或升级UI库。

## 3. 验证

先验证新增协调单元，再在轮次收尾集中做原生检查。

- [全量93个Rust测试](evidence/P2-010-tests.log)通过。新增5个测试覆盖：预览零任务、过期版本拒绝、空主题必须确认、重复确认/改版本不能二次发送、缺密钥零任务、三种结果持久恢复、并发点击拒绝、丢弃窗口结果接收端后仍可靠完成、预览后附件损坏拒绝。协调测试注入Fake Vault和模拟投递结果，不是实际SMTP；实际TLS/STARTTLS故障覆盖沿用并重跑P2-009协议测试。
- fmt --check、workspace全目标check --locked、clippy -D warnings、release构建通过；仅保留既有mail-protocol stub manifest提示。

- [原生发送预览探针](evidence/P2-010-send-review.json)通过：从邮件窗口进入账号草稿，以原生输入接口填写正文和收件人，保存后进入无主题预览；取消预览，等待字段重绘解除只读，再输入错误地址并验证无法进入确认。SQLite发送任务为零；没有调用发送确认、系统密钥库或网络。初次探针在取消后的同一回调立即输入，早于字段恢复的重绘时机，已修正为复用实际取消动作并在下一轮输入后通过。
- [跨进程写信回归](evidence/P2-010-compose.json)通过：四字段、正文格式、慢保存期间继续输入、附件源文件删除后的恢复。探针增加可指定本轮证据位置，未覆盖历史证据。
- [9项原生生命周期回归](evidence/P2-010-lifecycle.json)通过。协调单测验证活跃发送不会因丢弃接收端而取消；实际有网络投递进行时的GUI退出等待尚未单独端到端验证，不把空闲退出回归扩展为该结论。

上述集中检查分别验证原生确认路径、模拟协调与持久化、真实本机TLS协议分支，没有贯通真实Secret Service、真实服务商和UI发送全过程，也没有单独人工核对排版。未向外部收件人发送邮件。

## 4. 限制与下一轮

单账号写信/阅读仍分独立技术窗口，收件人chips、按需展开Cc/Bcc、回复/转发、历史任务独立页面未完成；远端草稿上传也未实现，但按主基线 §9 随 P3 离线/草稿完善推进，不作为新增 P2 待办。当前新增发送确认和协调闭环，不宣称P2整个真实账号闭环已验收。

下一轮优先实现IMAP已发送副本保存与只重试副本，再实现受控重发/停止处理及故障详情。真实SMTP投递、Secret Service真实账号贯通及持续使用仍待操作者授权与实测。

# P3-006b 持久草稿上传与结果核验

日期：2026-11-17。基线：P3-006a `d1c1b28`。本轮接入本地→服务器上传与上传前基线保护，**P3-006整体仍未完成**。

## 已实现

- schema14→15新增 `draft_sync` 与 `draft_uploads`，保存本地版本、原件基线、固定上传MIME、唯一Message-ID和执行状态。数据库触发器跟踪远端账号草稿新增/编辑；已有转换副本迁移其原件和转换版本。保留迁移前备份及未来版本拒绝。
- 本地保存行为不变。编辑停止约5秒后后台合并上传；编辑窗口保存成功关闭时请求合并调度。没有草稿目录时提示选择，不猜名称或创建目录。本地空白占位草稿不上传；已有同版或更新版SMTP任务的草稿不启动新上传。
- 独立草稿工作循环复用StorageWorker、Secret Service及主动IMAP限流，同账号串行；遵循全局/账号暂停，失败退避60秒，按上次尝试时间轮转，错误不阻塞其他账号。收到认证拒绝暂停对应账号。
- 准备MIME和执行权均先持久化再发APPEND。重启、断连或结果不明只能查询原唯一Message-ID并获取原始字节核验，不直接再次APPEND。协议证明正文尚未被接受时可恢复prepared，保留同一固定快照稍后尝试；未知结果没有此分支。
- 使用 `\Draft \Seen` APPEND；即使有APPENDUID，也重新查标识、读原件并逐字节核验，成功后才更新共同基线。核验期间本地继续编辑时，仅确认旧版本，较新版本保持待同步，不被覆盖。
- 上传前核对已关联原件的目录、UIDVALIDITY、UID与原始字节；变化/缺失时暂停为冲突。发现同UID不同内容时保留新旧原件，不覆盖本地副本。上传前后账号配置变化不被当成原账号成功结果。
- “服务器草稿”页显示待同步、已核验、失败、冲突及结果不确定，轮询读取实际后台状态。旧服务器版本保留；本轮不执行删除/EXPUNGE。

## MIME复用与已发送副本修复

复用 `outgoing` 的地址、日期、附件和MIME构建校验。草稿允许无收件人，保留Bcc，并带有受控富文本JSON部件；`prepare_draft`只返回MIME字节，不能把它作为SMTP提交对象。SMTP既有路径继续拒绝空收件人、隐藏Bcc且不加入草稿JSON。

重新导入时仅在JSON可解码、唯一、且与实际plain/HTML正文一致的情况下恢复富文本格式，过期或不匹配的JSON不能覆盖外部修改。经过验证的模型部件不作为用户附件展示。外部HTML仍需明确转换并保留原件。

复用APPEND实现时补齐了字面量之后的独立CRLF命令终止符；此前只写MIME字节，不能依赖MIME末尾换行代替IMAP命令终止。已发送副本相关8项本机TLS测试随之核对该字节边界并通过，未改变SMTP发送状态机。

## 参数、边界与006剩余

本轮草稿固定MIME、远端核验和原件保留仍沿用8MiB边界；超限保留本地并明确失败，不截断上传。这是006尚待消除的兼容缺口，不能把收件附件1GiB或发件25MiB误写为服务器草稿已支持的大小。

尚未完成：定期服务器草稿发现/导入、服务器替换UID后按安全版本关联查找、远端单独变化时更新可编辑副本、完整冲突记录与“保留两份/选版本”入口、超8MiB草稿原件处理，以及已发送草稿的远端关联收尾。当前冲突暂停后可查看已保留原件/本地副本，但没有伪装可用的解决按钮；DraftConflicts/ResolveDraftConflict继续Unsupported。已知旧版本保守保留，不实施无安全依据的删除。这些仍属于006，不转移为007或悄悄取消需求。

结果不确定且查询不到唯一快照时持续保持不确定，用户新编辑不会绕过它生成另一份上传；不会自动发送SMTP或重复APPEND。没有真实服务商兼容/原生GUI操作者验收结论。磁盘预算和淘汰保护留007，新增上传快照及原件必须纳入保护。

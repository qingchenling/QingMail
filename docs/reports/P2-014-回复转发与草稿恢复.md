# P2-014 · 回复、转发与草稿恢复

> 历史轮次记录：下文“当前/尚未”均指本轮结束时；最新实现与待办以 [P2 当前状态与剩余工作](../P2-当前状态与剩余工作.md) 为准。

- 日期：2026-11-16
- 状态：实现、120 个 Rust 测试与构建门禁通过；原生回复/转发流程与真实账号未验收。

## 1. 本轮范围

完成 B 项：

1. **回复 / 全部回复 / 转发**：从阅读窗口生成收件人、主题与清理后的可编辑引用，创建新草稿并进入既有写信/发送流程；支持 Ctrl+R / Ctrl+Shift+R / Ctrl+Shift+F。
2. **区块编辑反馈与续项**：列表/引用中回车续项、空条目结束区块；引用行在编辑器中可见底纹、签名淡化，并显示当前区块。
3. **清理后的 HTML 粘贴**：显式“粘贴 HTML”动作，经 `mail-content` 清理与受控转换后插入光标处。
4. **草稿失败处理**：任何草稿都可“另存草稿”；加载失败时提供“另存原始数据”和“放弃并新建草稿”，不自动覆盖。

不新增 schema、不新增依赖、不改变发送状态机。

## 2. 实现

### 2.1 原始邮件数据

`MailContent` 增加解析后的 `from/to/cc/reply_to` 独立地址、`date_unix/date_text`。回复/转发只用地址字段，不把显示名拼进收件人；引用只用清理后的 `plain`，不把原始 HTML 塞回编辑器。

### 2.2 收件人与主题

- 回复：优先 `Reply-To`，否则 `From`；排除当前账号地址。
- 全部回复：`Reply-To/From` + 原 `To` 进收件人，原 `Cc` 进抄送；大小写不敏感去重，并排除当前账号。
- 转发：不预填收件人，正文带最小头部块（发件人/日期/主题/收件人）。
- 主题：回复加 `Re: `、转发加 `Fwd: `；已有 `Re:`/`Fwd:`/`Fw:`/`转发:` 前缀时不重复。
- 引用正文：纯文本 + 受控 `Quote` 块；超长时截断并注明，不拒绝草稿。
- 回复/转发总创建**新草稿窗口**，不覆盖正在编辑的草稿；草稿经存储线程创建后恢复字段与正文。

阅读窗口新增“回复 / 全部回复 / 转发”和快捷键。没有发件账号的合成阅读窗口不显示这些入口。

### 2.3 区块编辑反馈

- 列表或引用中按回车：新行继承同一区块；空条目回车结束区块并交回普通换行。
- 引用行在编辑器中显示底纹，签名淡化；编辑区上方显示“当前区块：段落/列表/引用/签名”。
- 这样不引入 HTML 编辑器，也不把右侧预览当作唯一反馈。

### 2.4 HTML 粘贴

- 新增 `Draft::from_html`：`ammonia` 清理后转成受控 `Draft`，保留段落、粗体、斜体、链接、列表、引用；脚本/样式/资源标签被移除。
- 新增 `Draft::splice`：把清理后的文档插入光标/选区，属性随文本一起搬运。
- 写信工具栏提供显式“粘贴 HTML”。**限制**：GPUI 的剪贴板只暴露文本，拿不到浏览器的 `text/html` 富文本格式；普通粘贴仍是纯文本。本轮实现的是“对剪贴板中的 HTML 文本做清理转换”，不是系统级富文本粘贴；该平台约束按已知限制记录，不宣称已完成富文本剪贴板支持。

### 2.5 草稿失败处理

- “另存草稿…”把当前收件人/主题与纯文本正文写入用户选择的文件（0600）。
- 加载失败时显示“另存原始数据…”与“放弃并新建草稿”：
  - 原始数据直接从存储对象读取，即使正文 JSON 已损坏也能取出；
  - 放弃只删除草稿行与关联，保留对象文件，然后强制创建新草稿，不静默覆盖原文件。
- 原有保存失败重试与保留窗口行为不变。

### 2.6 链接与格式

沿用既有加链接/去链接、粗体/斜体、列表/引用/签名按钮；本轮补充当前区块反馈与续项，不另造编辑器。

## 4. 边界与下一轮

- 没有设置 `In-Reply-To`/`References` 线程头：冻结快照与 MIME 构建层尚未携带原邮件 Message-ID；收件人客户端不会把回复串成会话。需要单独扩展快照字段与协议测试。
- 富文本剪贴板受 GPUI 限制；如需真正 `text/html` 粘贴，需要平台侧剪贴板扩展或 ADR 明确降级。
- 回复引用只含纯文本；原邮件的复杂表格/图片不会进入引用，这是受控模型的既定取舍。
- 中文斜体缺字形继续作为已知限制，不新增字体工程。
- 真实账号回复/转发、失败草稿恢复、文件另存与原生 UI 排版仍待集中验收。

# P2-008 · 发件账号与草稿关联

- 日期：2026-11-16
- 状态：实现与单元验证通过；新增窗口交互未单独人工验收。

## 1. 行为

邮件窗口“写信 / 当前账号草稿”将当前账号的稳定ID和已保存邮箱地址传入独立写信窗口；无账号时禁用入口。窗口固定显示发件账号及“草稿仅本地保存”。首次创建空白账号草稿，不插入技术验证示例文字。新建、列表、切换和重开均限定账号，收件人/主题/富文本/附件继续复用P2-007完整文档保存流程。

主窗口原编辑入口继续打开未关联账号的本地草稿空间；既有本地草稿保留，不会被改绑或复制到远端账号。账号草稿也仅保存到本机SQLite，不上传IMAP草稿箱、不访问凭据、不创建发送任务。本轮不实现SMTP、回复/转发或远端草稿同步。

仍只允许一个编辑窗口：请求另一个草稿空间时激活原窗口并明确提示先保存关闭，发件账号不会静默切换。可关闭后从目标账号重新打开。此约束防止编辑中换账号造成草稿归属或附件混淆。

## 2. 存储和限制

存储工作线程新增显式账号的打开/新建/列表/选择接口；进入时核对账号存在且为remote，草稿读取按账号和草稿ID查询，底层外键防止跨账号选择。测试核实account()返回Option，已处理None，避免把本地空间或缺失账号当作有效发件账号。

沿用schema5，原local_editor表名称为历史命名，现用于单编辑上下文的当前草稿引用，新增通用select_editor_draft方法；原select_local_draft仍保留local校验。当前只记忆最近一个草稿空间的选中项：如果期间打开了另一个空间，返回时回退到该账号已有草稿列表的第一项，不保证恢复每个空间独立的选中项。所有草稿内容与归属均保留，可用列表重新选择；每账号持久选中记忆后续完善。

已有账号的草稿不随配置字段变化自动迁移，本轮不提供在草稿内修改发件账号的操作。界面邮箱地址来自已保存账号配置。产品上的账号草稿文件夹整合、按需展开Cc/Bcc、收件人chips与最终写信布局仍未完成。

# P0-006：原生富文本编辑验证与差距

> 历史轮次记录：下文“当前/尚未”均指本轮结束时；最新实现与待办以 [P2 当前状态与剩余工作](../P2-当前状态与剩余工作.md) 为准，不重复执行已完成工作。

- 日期：2026-11-16
- 阶段：P0 迭代 4；依据主文档 §6.2、§9、§11 与 ADR-0006。
- 状态：原型实现、自动门禁与字体修正后人工复验完成；保留完整首版富文本能力缺口，不以编译通过替代真实输入法验收。
- 范围：合成草稿，不连接真实邮箱，不发送邮件，不使用 WebView。

## 1. 原型方案

锁定的 GPUI Kit 0.9.1 不提供完整富文本编辑器。其 `EditorState` 提供原生平台输入、选区、软换行和 `InputHighlighter` 样式接口。本轮复用该输入引擎，用应用持有的受控草稿投影粗体、斜体和链接下划线；禁用代码行号、折叠、自动括号和智能缩进。使用普通字体。

`mail-content::draft::Draft` 保存版本、纯文本及逐 Unicode scalar 属性（粗体、斜体、允许列表链接、段落类型），不保存不可信 HTML。UI 收到不可变 `InputEditsEvent` 后按实际 UTF-8 编辑范围更新模型；平台 IME 使用 UTF-16 的边界转换仍由原生输入引擎承担。上游预编辑不发普通 Change，提交可能发整篇替换；临时文字仅作样式投影，提交后以实际首尾差分保留外围格式，不将整篇属性重置。空文档/尾段有哨兵属性。正文上限 32 KiB，文件上限 8 MiB；超过编辑上限时恢复前一个有效模型并显示错误。

- 行内格式在输入区直接呈现；列表、引用、签名的结构在右侧受控 HTML 预览中呈现。
- 导出 `text/plain`（含列表/引用标识）与允许列表 `text/html`。HTML 从模型生成，文本和链接属性转义；链接仅允许无凭据的 HTTP(S)/mailto。
- 粘贴仅采用原生输入引擎的纯文本；不解析或回灌剪贴板的原始 HTML。预览链接禁用打开。
- 统一文本/格式历史，最多 32 个快照；预编辑阶段合为一次历史，不将组合中的草稿自动保存。输入区捕获原生 Undo/Redo action，防止其内部纯文本历史绕过格式历史；Ctrl+Z/Y、Ctrl+Shift+Z 与工具栏使用同一历史。
- 连续普通键入目前逐编辑事件撤销，不模拟成熟编辑器的按词事务合并。空选区粗斜体设置作用于后续连续键入，移动到其他位置后按插入位置继承属性。

## 2. 后台自动保存与恢复

验证槽位是**当前工作区 `target/p0-editor/draft.json`**，不是产品正式存储目录；`cargo clean` 会删除它。单独的 `--editor-probe` 使用 `target/p0-editor-probe/p0-editor`，不覆盖人工草稿。

- 300 ms 检查一次，停止输入至少 750 ms 且不在预编辑时保存；保存中继续编辑，旧回执只确认对应 revision。
- 文件编码、写入与同步在后台进行；已确认保存状态只在文件同步、原子替换、目录同步成功后更新。
- 目录 fd 锚定，目录 0700，文件 0600，随机临时文件、NOFOLLOW/EXCL、fsync + rename；单写者锁防止两个验证窗口竞争覆盖。
- 打开窗口时后台恢复，恢复完成前输入只读。损坏/不支持版本或锁失败明确提示并停用本窗口自动保存，原文件不改动。
- 关闭或崩溃后恢复最后确认保存的版本；最后不足约 1 秒的未保存输入不保证保留。本轮没有实现关闭前刷新/确认流程（交由下一迭代生命周期验证）。

## 3. 验证与证据

自动门禁 `fmt --check` / `check --locked` / `test --locked` / `clippy -D warnings` / release build 均通过；18 个 Rust 测试（内容 12、UI 1、其余 5）。现有 stub manifest 的 5 条未用依赖提示仍在，无新增 Rust/Clippy 警告。

[原生输入协议探针结果](evidence/P0-006-editor-probe.txt)：实际窗口中验证 UTF-8 选区、UTF-16 emoji 替换、中文预编辑/提交、文本与格式撤销/重做、粗斜体/链接/列表导出、后台保存/重读相等。模拟后台保存耗时 900 ms 时，下一次输入仍正常进入模型；最终确认版本与最新草稿相等。该检查证明输入不等待保存任务，不是完整输入延迟基准。

首次人工验收：操作者报告“粗体和斜体显示没有效果”，本轮验收不通过。定位发现 GPUI 的 `sans-serif` 在本机解析的普通/粗/斜均为 FontId(1)，静态/模型探针遗漏了实际字形选择。修正：从 GPUI 可见字体中选择明确字体族（本机 Noto Sans，备用 Liberation Sans / DejaVu Sans / 系统字体），同时应用编辑区和预览区。新增真实字体解析探针，Noto Sans 普通/粗/斜分别为 FontId(14)/(7)/(9)，并断言所选字形不相同。没有变更依赖快照或系统字体配置。

[字体对照截图](evidence/P0-006-font-style.png)（仅合成内容、125%、原生 Wayland；截于编辑区修正后、预览字体修正前）：编辑区西文粗斜体、中文粗体有区别；本机 CJK 回退字体没有斜体字形，中文斜体仍不倾斜，列为未解决缺口，不用模型标志代替显示验收。预览区同样须应用明确字体族（对照时发现只修编辑区不足）。操作者复验回答：“上述修复正常，中文斜体作为已知缺口记录”。该确认覆盖英文/数字粗斜体、中文粗体、右侧预览及撤销/重做；不将它扩大为此前未单独确认的真实 IME 取消、鼠标跨格式选区、剪贴板和关闭重开完整矩阵全部通过。

| 实测项 | 结果与证据 |
| --- | --- |
| 模型 Unicode 编辑/格式/JSON 往返、拒绝危险链接 | Rust 测试通过 |
| 文件保存/重读、权限、锁、损坏文件、符号链接 | Rust 文件系统测试通过 |
| 原生标记预编辑/提交、UTF-16 emoji 范围 | 原生协议探针通过；真实输入法完整矩阵仍待专项确认 |
| Ctrl+Z/Y 与格式/文本统一历史 | 原生探针通过；修正后操作者复验正常 |
| 保存期间继续输入、保存回执版本隔离 | 原生窗口 900 ms 慢写探针通过 |
| 西文粗斜体、中文粗体、预览 | 字体修正后操作者复验正常 |
| 中文斜体 | 未解决；操作者同意作为已知缺口记录 |
| 草稿恢复 | 程序原子写入/重读验证通过，新版窗口已恢复已保存草稿；操作者尚未单独确认完整关闭重开矩阵 |
| 首版全部基础富文本功能 | 未通过完整验收；列表/引用所见即所得、附件、引用导入等仍需补齐 |

原生探针通过 `--editor-probe` 调用实际平台输入协议，包括 UTF-16 范围、标记预编辑与提交；它不代表真实 Fcitx/中文候选窗操作。预编辑/提交在同一次原生更新中检查，以免实际输入法异步取消模拟预编辑；未据此宣称跨候选输入过程通过。

运行：

```sh
cargo fmt --all -- --check
cargo check --workspace --locked
cargo test --workspace --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo build --release -p mail-ui --locked
WAYLAND_DISPLAY=wayland-1 VK_DRIVER_FILES=/usr/share/vulkan/icd.d/intel_icd.json ./target/release/mail-ui --editor-probe
WAYLAND_DISPLAY=wayland-1 VK_DRIVER_FILES=/usr/share/vulkan/icd.d/intel_icd.json ./target/release/mail-ui --editor-demo
```

## 4. 差距与首版影响

| 能力 | 本轮实现/限制 | 首版前需补齐 |
| --- | --- | --- |
| 中文 IME、emoji、选区/光标 | 复用原生协议，协议探针与真实输入法验收分开记录 | 组合输入取消、候选窗位置、跨行/跨格式鼠标选区实测 |
| 粗体、斜体、链接 | 原生输入内样式投影；链接地址在独立字段设置；本机中文回退无斜体，中文倾斜未解决 | CJK 斜体/合成倾斜方案、活跃格式工具栏状态、混合选区、链接编辑交互 |
| 段落、列表、引用、签名 | 受控结构可编辑、可导出；列表缩进/项目符号仅预览可见 | 正文区块所见即所得、Enter 列表续项/退项、签名语义与嵌套引用 |
| 撤销/重做 | 统一快照，预编辑合并；普通键入逐事件 | 按词合并、选择方向/视口恢复、长草稿内存优化 |
| 粘贴 | 纯文本粘贴，不信任原始 HTML | 清理后的基础富文本剪贴板导入；本轮未承诺保留外部格式 |
| 回复/转发引用 | 模型不接受原始 HTML；可编辑受控引用 | 与阅读管线连接的清理后导入和引用折叠，尚未实现 |
| 附件 | 未接入写信模型 | 附件生命周期、丢失提示和草稿引用保护 |
| 序列化/自动保存 | 本地单槽验证、版本/范围校验、后台原子写入 | 正式存储、多草稿、迁移、关闭时刷新/崩溃恢复矩阵、服务端同步 |
| 性能/缩放 | 有界正文和历史，后台写入 | 大文档输入延迟/内存测量，100%/150%/200%、多显示器与辅助功能 |

结论边界：这是一条可继续验证的原生受限编辑路径，尚不能据此宣称首版完整基础富文本写信通过。没有修改 ADR-0006 或将首版降级为纯文本。若后续决定缩减列表等首版要求，必须先另作 ADR；本报告保留缺口以供决策。

# P2-006 · 正文按需下载与缓存阅读

- 日期：2026-11-16
- 状态：实现与自动验证通过；操作者已确认验收通过，真实邮箱兼容性未验证。

## 1. 范围与行为

邮件窗口选择邮件后点“打开正文 / 缓存”：先通过存储工作线程查找完整MIME缓存；命中后无需密钥或网络，直接打开复用的简化阅读窗口。未缓存时读取系统密钥库凭据，建立验证证书的IMAP连接，EXAMINE核对UIDVALIDITY，以UID BODY.PEEK[]获取完整MIME。等匹配的成功响应后才持久化，再读回校验缓存并解析。不开启自动下载，不改变远端已读状态，无SMTP发送。

完整MIME上限8MiB，包含其中的附件；协议预算9MiB、正文阶段60秒软期限，沿用5秒socket超时。下载不是附件分段按需获取，超限邮件给出错误。系统DNS尚无独立取消期限。字面量按声明长度读取，避免大正文按换行重复扫描。

正文窗口复用受控HTML、中文正文、纯文本切换、字号、CID内嵌图、附件保存、远程资源默认阻止和安全浏览器副本。实际邮件隐藏合成样本选择栏。浏览器资源策略未修改，本轮验证副本生成及既有安全解析测试，不声称重新执行了真实浏览器资源探针。

## 2. 持久化与失败语义

SQLite升级到schema5，升级前保留私有备份。message_bodies按账号/文件夹/UIDVALIDITY/UID关联不可变body对象，外键保证账号和对象类型一致；epoch重建自动移除旧关联。对象采用既有私有目录、大小和摘要校验，文件同步后事务写入引用。重复写相同内容幂等，不同内容或损坏对象拒绝覆盖。

下载失败、截断、UID不匹配、epoch变化或持久化失败均不报告成功，保留既有索引和缓存。关闭邮件窗口后已启动的后台下载可能继续完成并保存；不会自动重试。未知提交结果可能留下孤立文件，统一孤立对象回收尚未实现。

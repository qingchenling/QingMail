# P3-006a 服务器草稿原件与转换

日期：2026-11-17。基线：P3-005 `fe94409`。本轮是006的首个可用增量，**不是双向服务器草稿完成报告**。

## 交付

- 原生“服务器草稿”入口，复用M3E控件、账号列表、阅读器及编辑器，不新增页面组件体系。按账号查看本地原件和服务器扫描结果。
- 使用LIST的 `\Drafts` 特殊用途属性，保留歧义；只有唯一可选目录才自动选择。用户可明确选择/更换本账号目录；不猜名称，不创建或删除文件夹。已有手选目录被服务器移除后不能继续导入。
- 只读EXAMINE、UID SEARCH ALL，不受最近90天索引限制。搜索响应最多10000个UID、展示最新200个；超限失败，不将未展示数据推断成远端删除。
- 用户点击后读取完整原始MIME（沿用8MiB边界和UIDVALIDITY/UID核对），不会读派生阅读MIME。网络过程中账号配置变化时拒绝关联；返回原件保存结果后才显示可查看/转换。
- schema13→14新增 `server_draft_folders` / `server_draft_sources`，迁移前备份；原始对象不可变，账号/目录/epoch/UID/原始哈希去重，同一UID出现不同内容仍保留旧版本。账号移除清理新增关联。
- 原件可离线查看，经现有安全清理；HTML原始字节与脚本等仍在私有原件对象中保留，展示不会执行它们。
- “转换为编辑副本”要求再次确认，明确说明纯文本转换会丢失HTML排版。保留To/Cc/Bcc及附件；损坏MIME/编码、超32KiB编辑模型、非法附件名等拒绝转换，不覆盖原件。重复转换返回同一份已编辑副本，不重新生成或覆盖。
- 附件导入/草稿写入复用既有Store方法，改为可嵌套保存点；外层保存点使附件、草稿、转换关联一起成功或回滚。失败写入可能产生无引用对象文件，沿用对象清理边界，不把它们当作有效草稿引用。
- IPC增加类型化原件列表/扫描结果、目录设置与转换命令；原件内容通过既有受控阅读资源传输，不传密码或任意路径。转换命令沿用持久请求结果，可查询/去重。
